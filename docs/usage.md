# 使用手册

按操作查：先加项目，再让 Leader 派工，用卡片跟踪，看板上验收。安装与第一条完整路径见 README 与[上手](getting-started.md)；做不到的事见[已知限制](limitations.md)。

## 加项目

左栏「项目」区块点「加项目」，选一个目录。项目当场建好并绑定一个 Leader 会话；点项目行就是打开这个 Leader——它不在项目树下单独占一行。

- 宿主只服务 browse 选择器时（SSH 启动、无 display 的 Linux）：点「加项目」→ 应用内目录浏览（可上一级、新建文件夹）→ 选目录 → 建成。
- 点标题「项目」收起 / 展开；新建项目时自动展开。
- 改名：行尾「更多」→ 重命名；目录名不合法时退回输入框；同名目录依次 `repo`、`repo-2`。
- 删除：二次确认，只删记录；文件夹、会话与工作区都保留。
- 排序：拖动项目行。
- 目录被删或移走时，打开会先提示。

Leader 会话空着时，输入框上方有引导条，可以了解用法或初始化 `LEADER.md` / `SLOTS.md`。

## 派工

分两步：

1. `spawn_worker({ name })` 建一个常驻 worker 会话并立即返回会话 id，但 worker **还没开工**。`name` 同时是会话标题；可带 `cardId` + `slot` 绑卡片槽位，也可带 `model` / `effort`（不填回落 `SLOTS.md` 的槽位默认，再回落 Leader 当前模型）。
2. `message_worker({ sessionId, message })` 投第一条消息，worker 才开始跑；之后再用就是续聊。worker 忙时消息插进当前轮次的下一步，空闲时立即开工。

worker 是普通会话，在项目树下有自己的行，可以打开直接输入。它每跑完一轮，Leader 会被唤醒并收到一条回报气泡（产物摘要或失败原因）；不需要轮询，worker 也不用调工具交作业。

卡必须是**本项目**的、`active` 状态才能绑；跨项目或已关闭的卡会被拒绝。

派工前可用 `list_worker_models` 查 route：不传参列 provider，给 `provider` 列 model，再给 `model` 列 effort（给 `model` 必须同时给 `provider`）。

### worker 名册上限与复用

每个项目最多 50 个未归档 worker。到顶时 `spawn_worker` 不新建，而是按最久未用列出本项目的空闲 worker 供复用；挂着未完成卡的不能接。确实要新建传 `force`。

## 看 worker 在做什么

- **回报气泡**：出现在 Leader 会话里，点 worker 名字跳到它的会话。
- **`read_worker_session({ sessionId, turns })`**：只读，不唤醒 worker，看它这一轮的任务、正文、工具调用与失败原因。`turns` 默认 2、最多 20，`offset` 往前翻页。
- **巡查**：Leader 发起的一轮超过 **15 分钟**没有回报，会收到带「【后台巡查】」前缀的提醒，附 worker 名字、挂着的卡与回看建议。它只是提醒，不是失败；本插件没有中止手段。

长时间没动静时，先 `read_worker_session`，再决定继续等、用 `message_worker` 纠偏，或请人打开那个会话处理。

## 卡片

卡片记录任务事实，按项目归属，编号全局递增、不复用。

- `create_card`：建卡，`title` 必填，`spec` 写目标、范围与验收。只有 Leader 能建。
- `update_card`：改卡；改内容带 `expectedRevision` 防并发覆盖。worker 也能用，但只能改自己挂着的卡，且只能动 `links`——标题、规格、状态、分类、排序与槽位归 Leader。
- `list_cards`：查卡，默认只列本项目 `active` 卡，一页 20 张；传 `cardId` 读单卡，`scope=all` 跨项目。只有 Leader 能列。
- `read_card`：worker 找回自己任务的入口；不传 id 时读唯一绑定的卡。

链接只挂交付物入口（PR / Issue / 文档 / 成片），不挂评论锚点；`links` 整体替换、`addLinks` 增量追加，两者互斥。每条链接要有 `label`；`url` 给了就必须是 http(s) 地址。

卡标 `done` 或归档会释放槽位，worker 才能接下一张；挂着未完成卡的 worker 不能接别的活。`kind` 是卡面头部的分类短标签。

## 看板

右栏「看板」Tab，**只对项目会话展示**：按当前会话所属项目拉卡。Leader 建卡后自动打开或聚焦。

- 卡面：编号 / 分类、标题、信号灯、链接与会话入口。点卡面开详情。
- 详情：说明与链接可编辑；页脚可删除卡片（二次确认、硬删、编号不复用）。点链接新标签打开，点会话入口进对应会话。
- 信号灯：等你输入 / 需注意 / 执行中 / 未读 / 空闲 / 状态未知 / 无信号，点开即灭。
- 模式：设置 → Leader Agent → 任务看板，选「工作模式」或「炫酷模式」。炫酷是演示用的线路图。
- 已归档的卡不在看板渲染。

## 项目管理

左栏项目区块：

- 点项目行打开 Leader；点行首格子展开 / 收起该项目的会话（worker 与被换下的 Leader）。
- 会话行默认 5 条，「展开其余」加一页；运行中与完成未读不会把列表撑开，绿点可能折起，只有当前会话保证可见。
- 按最近使用倒序。
- 悬停行尾可归档，归档会摘掉卡上的槽位绑定；会话正在跑时先问「停止并归档」。
- worker 标签可切换；× 只关标签。
- 换 Leader：原会话退役；原班 worker 与未投递回报改投新 Leader。
- Leader 会话不显示「已编辑 N 个文件」汇总。

## 项目提示词

在项目目录写两份文件。它们只贡献提示词，不授予工具权限；改文件在下一个模型请求生效。

- `LEADER.md`：Leader 怎么指挥——职责、拆卡粒度、派工要求、验收口径。Leader 会话每轮自动注入，不需要绑定。
- `SLOTS.md`：按 `## <槽位名>` 分节写角色方法与人设；卡片 `slots` 把槽位绑到会话，被绑 worker 每轮注入对应正文。顶部 frontmatter 可声明显示名 `label` 与默认 `model` / `effort`，模型只在建 worker 时定下。

槽位名用小写字母、数字、下划线、连字符，最长 32 字符；没写 `SLOTS.md` 时回落内置 `dev` / `review`（正文为空）。示例见[上手](getting-started.md#三两份文件leader-的人设worker-的工作方法)。

`COORDINATOR.md` 只是给旧工具找 `LEADER.md` 的兼容入口，不参与注入。

## 设置

左下角菜单 → 设置 → Leader Agent：

- **任务看板**：工作 / 炫酷模式，所有项目共用。
- **自动续行**：Leader 最多被 Worker 唤醒多少次（默认 200，范围 1–10000）。撞上限后回报留在队列，直到你在 Leader 会话里开口；调高会释放，调低不会。
