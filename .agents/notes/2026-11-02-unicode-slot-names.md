# 槽位名放开到 Unicode 字母数字

## 背景

槽位名的合法形态原本是 `/^[a-z0-9_-]{1,32}$/`，注释给的理由是「避免出现需要转义的字符」。这个理由不成立：槽位名的消费方只有三类——卡片 `slots` 的 JSON 键、宿主侧 `Map` 的键、以及注入提示词的纯文本（`renderRoleContext` 的「你当前承担「X」槽位的角色」）。它不进文件名、URL、CSS class 或 `data-*` 属性，没有任何一处需要转义。实际代价是中文项目没法用「开发」「审核」这类名字，只能写 `dev` / `review`，卡面上的槽位 chip 也跟着显示英文。

## 决策

- 合法字符集改成 Unicode 字母与数字，加上 `_` 与 `-`，长度仍是 1–32：`/^[\p{L}\p{N}_-]{1,32}$/u`。
- 仍然拒绝空白与标点。理由不是转义，而是**两边必须能对上**：解析器对 `## <槽位名>` 的标题做了 `trim()`，名字里带首尾空格时卡片键与解析结果永远不相等；`## 开发/审核` 这类名字在提示词与卡面上也难以辨识。零宽字符、控制字符同样落在被拒集合里。
- 组合标记（`\p{M}`）没有放进来：中文、日文、拉丁字母都不需要它；要支持天城文等文字再加，不在这一次的范围里。附带结果是名字的 Unicode 规范分解形式（NFD）会被拒——名字按字面比较，`SLOTS.md` 与卡片键必须用同一种写法（编辑器通常保存 NFC）。
- 规则抽成 `isValidSlotName` 并导出，`SLOTS.md` 解析器与卡片工具 `normalizeSlots` 共用。此前卡片工具完全不校验槽位名——写进 `Bad Name` 会成功落盘，解析器却整节忽略，注入静默变成空串。现在在写卡时直接报错。
- 卡片工具的 `slotsSchema()` 不再把 dev / review 当唯一合法键：`properties` 里保留这两个常见示例，其余名字走 `additionalProperties`。槽位集合的真源是项目 `SLOTS.md`，不是工具的固定枚举。

## 边界

- **存量卡片**：旧规则下写进去的槽位名只会是小写 ASCII，全部落在新规则内；没有迁移动作。真有非法名的卡，下次 `update_card` 传入该名时会被拒绝——这是刻意的 Fail Loud，不是回归。
- **`DEFAULT_SLOT_NAMES` 不变**：`discuss` / `dev` / `review` 只是「项目没写 `SLOTS.md`」时的回落骨架（正文为空），不是合法名白名单。
- **客户端不用改**：卡面 chip 直接显示槽位名（`src/client/board-card.js`），中文照常渲染；CSS class 是固定前缀，不拼槽位名。
- **`additionalProperties` 的输出侧影响**：`cardSchema()` 的 `slots` 也用它，宿主对工具输出做 schema 校验时会检查所有槽位条目必须有 `sessionId`。卡片写入路径已经由 `normalizeSlots` 保证这一点，不存在存量例外。
