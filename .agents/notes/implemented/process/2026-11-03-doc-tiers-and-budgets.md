# Agent Note: 文档按层归属，并给 standing docs 加体量门禁

Status: implemented

## Problem

宿主对文档有两道预算（注入预算只作用于 `AGENTS.md` 一类指令文件，另有 standing docs 的词数天花板），本仓一道都没有，`npm run check` 只查 Agent Note 格式与文档工具名。`docs/architecture.md` 因此长到宿主同位置文档的三倍，体量来自与代码同频变化的逐文件职责表与整节已知限制；开发节、README 与 `AGENTS.md` 还三处重复讲同一批开关。代价是改任何一处实现都要同步改架构文档，而它是「先读再改」的地图。

## Decision

- **一个事实一个归属**：分层表放 `AGENTS.md`（层 → 管什么 → 不写什么），改代码时只改事实已经变化的那一层；`docs/architecture.md` 只留有序地图（分层、运行时模型、数据流、持久化布局、宿主契约落点），逐文件职责表删除——文件头注释是权威来源。
- **限制与开发各自成文**：`docs/limitations.md`（限制是什么、为什么这样取舍）与 `docs/development.md`（开发环境、实例、构建契约、测试机制）承接架构文档对应两节；README 只留使用者向概览与命令速查，细节链过去。阶段编号一并删除。
- **计数口径：CJK 字符逐字算 1 + 其余按空白分词**，代码块与表格一并计入。`wc -w` 对中文失效（整段算一个词），会把万字文档测成小几百词；口径只求稳定与可解释，不追求与 token 数等价。
- **未登记文档同样变红**：门禁枚举根目录与 `docs/` 下的 Markdown 再比对清单，漏登记报 `UNREG` 并退出 1，不留「新增长期文档忘了登记就绕过预算」的旁路；单测另守一条真实扫描用例，脚本入口与用例能独立变红。
- **天花板按当前值留余量，超限先搬层**：红了按「搬到对的层 → 压缩 → 抬天花板」处理，抬天花板要在 PR 里写明理由。`AGENTS.md` 与高频追加的 `capability-gaps.md` 留得更多；上下限、`loose` 判定与「按当前值重算」归 [文档预算的余量上限](2026-11-04-doc-budget-headroom-cap.md)。
- **`.agents/notes/` 与 `.agents/skills/` 不设预算**：前者是历史累积，后者按需加载。

## Alternatives considered

- **保留架构文档的逐文件职责表**：与代码同频变化，文档长到宿主同位置的三倍；逐文件职责归文件头注释，架构只留地图。
- **用 `wc -w` 计数**：中文整段算一个词，万字文档会测成小几百；CJK 逐字 + 非 CJK 分词。
- **只给已登记文档设预算**：新增文档忘了登记就绕过；枚举根目录与 `docs/`，漏登记报 `UNREG`。
- **按当前值贴线设天花板**：任何改动都立刻红；留 5–12% 余量，超上限报 `loose`。
- **给 `.agents/notes/` 与 `.agents/skills/` 也设预算**：前者历史累积、后者按需加载；不设。

## Consequences

- 门禁只判体量，不判归属正确性：把细节搬到错误的文档里照样绿，避免重复靠分层表而不是机械判定。
- 同一事实写在两处时，只有其中一份先撞天花板才会被发现；两处都短就能长期共存。所以架构文档与服务层语义、限制清单重复的位置一律留指针，不两边各讲一遍。
- 章节搬迁会断锚点链接，本仓没有 Markdown 链接门禁：改结构时要自己 grep 一遍锚点；历史 Agent Note 里的旧锚点保持原样。
- 预算单位是体量代理、不是 token：中文 1 字与英文 1 词的信息量不等价，跨语言对比没有意义。
- 宿主的注入预算仍由宿主执行，本仓不重复实现；它只管指令文件，`docs/` 的体量由本仓门禁管。

收益：每类事实只有一个归属，长期文档有可执行的体量上限，新增文档漏登记也会被门禁抓住。

## Testing

`tests/doc-budget.test.js` 覆盖计数口径、超限、未登记与真实清单全绿；双向验证：新建不登记的 `docs/` 文件报 `UNREG` 并退出 1、计数口径归零后口径用例变红、给架构文档追加内容报 `OVER`，还原后全绿。
