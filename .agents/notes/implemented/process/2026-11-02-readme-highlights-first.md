# README 改成亮点优先：英文默认、中文对照与顶栏视觉层

## 背景

README 瘦身后机制细节已下沉到 `docs/`，但第一屏仍读不到「这套东西能帮我干什么」：开头是定义句、工程前提挡在第二屏、功能条目以工具名开头、最强的三个能力各只占一行。缺的是叙事顺序与视觉层，不是内容。

## 决策

- **叙事顺序：价值 → 机制 → 上手 → 编排 → 前提与限制**。tagline 与亮点在前；「怎么跑起来」用一张流程图加三条机制差异（工具面按身份裁剪、完成由机制结算并自动唤醒、worker 是常驻根会话）回答「为什么不是更聪明的 prompt」。
- **亮点按用户口径排定**：Leader 推进开发与 Review、右栏看板、`COORDINATOR.md` / `SLOTS.md`、多项目并行、`leader-mode`、读回 worker 会话。规模口径写「一次并行开发 10 个 feature」，不写具体 agent 数——没有实测吞吐读数，写死会在别人机器上立刻过期。
- **顶栏视觉层自足**：logo 是手写矢量 SVG，深浅两版用 `<picture>` + `prefers-color-scheme` 切换，无外链、无位图；徽章只写真实成立的状态（MIT、`engines.dsh` 下限、developer preview、npm 版本与下载量、CI、stars），用 shields.io 静态徽章。
- **英文默认、中文同级**：`README.md` 英文、`README_ZH.md` 中文，两版顶栏互相切换；默认英文是因为仓库面向 dsh 插件生态。中文版不是译文附录，两版各自的 logo 副标题随语言走。
- **双语漂移用三条约束压住**：章节顺序与锚点一一对应；行为变更同 PR 改两版；任一侧新增内容在对侧落到同一位置。没有机械门禁比对，这是明确接受的成本。
- **预览图入库并架在亮点之后**：用真实工作会话截图，不用示意图形冒充；上一版「不放预览图」因当时没有真图，条件变了结论跟着改。
- **职责边界不变**：机制论证在 `docs/architecture.md`、完整交互在 `docs/usage.md`，README 只给最短路径与指针；「前提」一节保留但后置，限制清单保持八条、每条一行。
- **不把 skill 写成「注入」**：每轮求值的是 `COORDINATOR.md` / `SLOTS.md` 与卡片事实，`leader-mode` 等由模型按需加载。

## 边界

- 纯文档加四份 SVG：不改代码与运行时行为，`package.json` 只动 `files` 把中文版带进包。
- 中文文档链中文版，避免锚点跨语言失效；历史笔记里的旧 README 指针保留原样。
- 真实截图带出本仓 PR 编号、worker 名与本机目录名，无凭据、令牌、第三方内容或用户数据；换别的项目做素材要先脱敏。
- `<picture>` 深浅切换在新仓库 UI 跟随 OS 主题而非 GitHub 手动主题（社区已知行为），只影响 logo 配色，不为它换写法。

## 验证

相对链接与锚点全量核查 0 broken、两版章节顺序一一对应；logo 深浅两版转 PNG 目视可读；成品图核过三栏布局与卡片渲染。
