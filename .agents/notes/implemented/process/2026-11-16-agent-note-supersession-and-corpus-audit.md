# Agent Note 的取代检查与一次全库体检

## 背景

`.agents/notes/` 一直没有 `AGENTS.md`：双轴口径在 `README.md`，写入约束只散在根 `AGENTS.md` 的「提交与 PR」里。宿主仓库已有对等文件，其核心不是格式，而是**每篇新笔记先做取代检查**。规模上来后，缺这一步的代价具体可见：笔记里有多组互相矛盾的现行事实，部分被推翻的决策仍以无指针的段落留着，还有从宿主抄来的 H1 前缀、漏网的 `Status:` 行与四套混用的验证/边界节名。

更主要的问题是正文写成了实现说明与验收日志：文件清单、宿主源码行号、CSS 数值、逐条复现读数、PR 复审过程占了大半篇幅，读完很难找到「到底定了什么」。97 篇合计 5,475 行。

## 决策

- **新增 `.agents/notes/AGENTS.md`，把取代检查写成动笔前的步骤**：已有主人 → 改那一篇、不新增重复记录；整篇被取代 → 同一 PR 删掉，只有仍值得留存的历史决策才移入 `archived/`；部分被取代 → 留下，在被推翻的节前加 `> **已被 [标题](…) 取代**：…` 指针并两篇互链。同一文件重申 `implemented/` 对代码现状负责、不写 PR 复审与复现流水账、`archived/` 冻结不回改；格式与双轴口径仍归 `README.md`，根 `AGENTS.md` 只加一行指针。
- **删除与归档的判据归 README**：整篇被取代且有历史价值的移入 `archived/{class}/`（冻结、不回改）；只描述小范围 UI 调整或纯机械改动的直接删；被否决的提案移入 `rejected/` 并写明理由；删除或归档都在同一 PR 修好入链。`AGENTS.md` 不重复这套判据。
- **全库体检：先合并/删除，再补指针，最后按决策笔记重写**：整篇被取代的删除（独有理由已并入现主人）；仍成立的旧篇加部分取代指针或删失效段；删掉复现过程、平台差异表与 PR 复审清单这类流水账；节名统一为 `背景` / `决策` / `边界` / `验证`。然后按「决策笔记」标准重写全部 93 篇——背景一段、验证 1–3 行、多数 ≤ 40 行，实现细节、数值、行号、复现过程、测试计数不写；标准写进 `AGENTS.md`。总量 5,475 → 2,638 行。
- **格式门禁补 `Status:` 这一漏**：此前只匹配行首 `**状态**`，所以 README 说「不要写」而门禁不拦，漂移就是这么长出来的。补成正则同时匹配两种写法，用例加正反两向：宿主式 `Status: implemented` 报违规，正文行内出现不误伤。

## 边界

- 没有建 `archived/` 或 `rejected/`：本轮删除的要么是正在误导现行行为的过期决策，要么其独有理由已并入现主人，没有需要冻结的历史快照；宿主那套 hash manifest 不在本仓规模内。
- 历史笔记保留「协调者」叙述：术语统一笔记明确豁免 `.agents/notes/`，只同步已改到的现行代码引用。
- 只删明确的过期与流水账：小范围 UI 笔记若仍记录判据或用户可见行为，不因篇幅短而删。
- 压缩以保留决策为界：实现读数与过程被删，判据、代价与失效条件保留；不确定的细节优先留一句而不是整段。
- 取代检查仍是人的判断：门禁只查结构、节名与链接可达，查不出「这段事实已被推翻但没写指针」。

## 验证

`npm run check` 全绿：93 篇格式合规、1121 用例通过、15 篇 standing docs 在预算内；笔记总量 2,638 行。撤掉 `Status:` 分支即用例变红、还原后全绿。删除文件后链接门禁当场报出全部断链，逐处改指现主人后归零；删除前 grep 确认相关机制已不在代码里。压缩是人工重写，没有机械门禁能判「决策是否还在」。
