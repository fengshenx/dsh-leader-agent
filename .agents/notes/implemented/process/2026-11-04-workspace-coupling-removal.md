# 清理工作区工具耦合

## 背景

本仓早期把发版手册放进外部编排工具的工作区 skill 目录，bot 凭据的默认路径也指向那个工具的数据根，门禁还因为那个目录开过特例。那个目录不是本仓的一部分：它的名字、skill 加载方式与凭据位置都跟着外部工具走，本仓的结构与发布链却依赖它。结果是 clone 下来的人看不到手册、门禁解释不了为什么有两个 skill 目录，产品名还散落在文档、源码注释与历史笔记里。目标是把耦合清零、功能不变。

## 决策

- **手册迁到 [docs/release.md](../../../../docs/release.md)**：摘掉只在 skill 语境有意义的 frontmatter，H1 下注明「维护者专用 / 不随包」。选 `docs/` 而不是 `.agents/skills/`：后者被 `files` 白名单打进包、并由 `SKILLS_DIR` 暴露给每个用户会话，而发版手册只服务维护者，出现在用户 `node_modules` 与 `skill` 列表里没有意义。代价是外部工具会话不再自动加载这篇手册，维护者从 `AGENTS.md` 的按任务查阅表进；它是 standing doc，漏登记会被预算门禁报 `UNREG`。
- **凭据目录改到 `~/.dsh-leader-agent/`**：与本仓 `~/.dsh` 的命名体系统一，`homedir()` 在 Windows 走 `USERPROFILE`、不引入 XDG 假设，也不写进任何外部目录；文件名常量由目录派生。
- **不做旧路径兜底**：兜底会把旧目录字面量写回仓库、让目标落空，也会让「文件还在别人家目录」静默长期存在，违背 Fail Loud。迁移窗口用「先复制、后合并」消掉——复制没做就合并时脚本报缺少凭证文件并以 1 退出，不会降级成作者身份。本机是复制不是移动：那份 App 凭据被别的工具共用，移动会让另一条通道立刻断。
- **仓库不再点名那个 App**：User-Agent 从 App 名改成 `dsh-leader-agent`（它只是 HTTP 头，不是身份），App 本身不改。
- **门禁收窄到单目录 + 显式补一份维护者文档**：`PROMPT_SKILLS_DIRS` 收窄为 `.agents/skills`，扫描面只认会进会话提示词的那一个 skill 目录；新增 `MAINTAINER_DOCS = ['docs/release.md']`——手册不进提示词，但会指挥人照做，工具名写错一样要到运行时才炸。扫描集合由提示词文档加维护者文档再拼 skill 目录，用例断言常量取值与脚本复用同一份。
- **打包黑名单换成通用规则**：逐条点目录黑名单改成「顶层以 `.` 开头一律不进包，`.agents/skills/` 例外」。这不是删防线而是收紧——将来任何新增的本地状态目录都默认进不了包；旧的黑名单断言原样留在用例里，证明没有放松；`.DS_Store` 规则保留以处理嵌套位置。

## 边界

- 不改 git 历史：旧提交里的路径仍在，验收以工作树为准。
- 包内容不变：`files` 白名单本来就不含工作区目录与 `docs/`，`.agents/skills/` 原样；迁移前后 `npm pack` 清单逐项相同，`engines.dsh` 与运行时行为不受影响。
- 本机只新增 `~/.dsh-leader-agent/`：旧目录的其它数据（会话、skills、mcp 配置等）不清理；是否弃用外部工具是另一件事。
- 验收口径是仓库内零字面量：全仓搜索那个工具名零命中（排除 `.worktrees/`、`.dev/`、`node_modules`）；历史笔记里的探针路径改成中性说法，读数不动。
- 通用点目录规则是行为变更：比逐条黑名单更严，白名单放宽时拦得住更多东西。

## 验证

`npm run check` 全绿（笔记、工具名、预算、语法、覆盖率）；四条双向验证：扫描面改回旧目录、点前缀判定退回、维护者文档从清单拿掉、删掉 [docs/release.md](../../../../docs/release.md) 而保留链接，各自变红。`npm run verify:pack` 清单与迁移前逐项相同、装机 smoke 通过。
