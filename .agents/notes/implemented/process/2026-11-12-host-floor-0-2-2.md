# 宿主下限抬到 0.2.2-rc.2

## 背景

- `engines.dsh` 原为 `>=0.2.1-rc.2 <0.3.0`。本机 npm 全局 `dsh` 与桌面版 CLI 都已是 `0.2.2-rc.2`；此前对不齐是因为 npm 的 `latest` 还停在 rc.1，rc.2 只在 `next` dist-tag 上。
- 0.2.2-rc.2 是桌面版实际发布的宿主，也是本仓左栏网格修复（#133）所对齐的 0.2.2 形态。继续声明 0.2.1 会把 0.2.1 全系与 0.2.2-rc.1 一起纳入支持面：客户端要同时兼容两代会话行 token / 网格，host 侧要避开 `definitions()`、registry `presetForSession()` 等已在 0.2.2 可用的方法。
- 0.2.2-rc.1 已被 rc.2 取代，且本仓没有在它上面验证过；把它留在范围内只会声明一个未验证的下界。
- 实测事实（rc.2）：`tools.restrict({ deny })` 仍对未注册全局名抛错，`get` / `schemas` 仍在；`tools.register()` 新增 `{ when }`（按 step 求值的谓词）；`ToolsService.definitions()`、registry `presetForSession()` 已可用；`permissionPresets` 的初始固定从 `session/created` 改为 `agent/created`（`{ prepend: true }`）。`agents.get()`、`AgentHandle.dispose`、`session/event`、`turn/end`、Typert 的 `version:1` / `typertRemote` 形状、`StateDot` / `UserMessageBubble` / `MarkdownText` 基线均未变。

## 决策

### 只抬下限

`package.json` 与 `package-lock.json` 的 `engines.dsh` 改为 `>=0.2.2-rc.2 <0.3.0`，上限 `<0.3.0` 不变。

### 约定句改、历史读数不改

全仓 70 处 `0.2.1-rc.2`（68 处在文档 / 代码 / 测试，另 2 处在版本文件）。改 25 处（23 处非版本文件 + 2 处版本文件），保留 45 处原始引用；保留的都是「在 0.2.1-rc.2 上实测 / 真机 / 源码阅读 / 复现」这类当时证据。另在新写的兼容注释里新增 7 处 `0.2.1-rc.2`（`src/client/project-section.js` 5 处、`src/client/worker-task-styles.js` 2 处），明确标成「旧下限」而不是当前下限。

约定句范围：`AGENTS.md`、README 与徽章、`docs/architecture.md`、`docs/limitations.md`、`docs/capability-gaps.md` 的现行规则、issue 模板、host / client 注释、tests 的下限断言与夹具说明。容易误读的历史句加了「当时」；`docs/capability-gaps.md` 开头注明读数仍按 0.2.1-rc.2 保留、新区间未逐条复测，并单独标注 `permissionPresets` 与 registry `presetForSession()` 在 rc.2 的变化。

测试夹具：`tool-gate` 仍只给 `restrict` / `get` / `schemas`，但理由从「下限没有」改为「故意比真实面窄」；`definitions` 未定义断言保留，作为夹具不变量。`board-styles` 白名单按 rc.2 产物与 ui-theme 复核；`dev-plan` 的 agent-team profile 版本改成 0.2.2-rc.2；`permission-inherit` / `worker-sessions` / `dispatch` 的注释同步到 rc.2 或「下限」。

### 现在可删的兼容代码（只列，不删）

- `src/host/agent-preset.js:78-102`：`recordedPreset()` 走 `sessionProjections.stateOf()`，并在注释里说 registry 没有 `presetForSession()`。新下限的 registry 已有该方法（实现仍走同一投影），可以把这条兼容路径收成 `presets.presetForSession(session)`；本 PR 不动。
- `src/client/worker-task-styles.js:11-15`：为旧下限基线缺少 `UserMessageBubble` 而抄了一份气泡样式。rc.2 的 `ui-primitives` 已有该导出，可评估改回静态 import（注意组件 props 与样式作用域）。
- `src/client/project-section.js:343-352,389-393,437-443`：`--dsh-sidebar-paint-inset` / `--dsh-sidebar-row-padding` / `--dsh-sidebar-label-gap` 的旧值兜底，以及 `:396-415` 的 24×24 / -4px 动作按钮形态。新下限只保证 0.2.2 形态，兜底与「另一版」注释可以删。
- `tests/tool-gate.test.js:15-25,191-196`：比真实面窄的夹具与 `definitions` 未定义断言。可直接换成 rc.2 的真实方法面；保留它的价值只是继续防「探针换面」。

（#133 的 0.2.1 分支另议；本 PR 不删任何兼容代码。）

## 边界

- 不改宿主仓库、不加 peer 依赖、不 import 宿主内部包。
- 主机对 `engines.dsh` 的校验分两处：`dsh plugin add` 在安装前拒绝不兼容包；已装 profile 在加载时跳过不兼容 bundle，应用本身仍能启动。后者不是硬启动失败，但插件等于没装。
- 本机 rc.1 时代的安装拒绝 / 加载跳过读数只作为历史；这次用全局 rc.2 复测通过。
- 历史实测记录不改写。`docs/capability-gaps.md` 的 0.2.1-rc.2 读数、`dsh-v0.2.1-rc.2` tag 对照、旧下限的 `platform.ts` / home-path 比对都保留，只补「当时」或新下限的旁注。
