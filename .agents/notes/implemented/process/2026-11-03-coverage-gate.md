# 覆盖率门禁：分母来自目录枚举，不是报告

## 背景

本仓此前没有覆盖率配置。用 Node 内置覆盖率实测，`all files` 行覆盖看起来体面，但 Node 只统计**被加载过**的文件：`src` 下从未被单测 import 的三分之一文件既不在报告里、也不算 0%，数字因此虚高，缺失集中在只能靠 e2e 覆盖的 client 组件与 CSS 模板。要对齐宿主「per-file 100% 行覆盖」的强度，先要解决的不是补测试，而是分母可信。

## 决策

- **分母来自 `src/**/*.js` 的目录枚举**：报告里没有、清单里也没有的文件直接红，提示「补测试，或在 unmeasured 里写明理由」；解析默认 reporter 表格时按目录缩进还原完整路径。旗标解决不了这层——`--test-coverage-include` 只过滤已加载文件，`--test-coverage-lines` 是全局阈值、报不出是哪个文件掉下来。
- **per-file 门槛默认 100%，存量按整数记账**：欠账登记在 `coverage-manifest.json` 的 `thresholds`，整数下限加没补的理由；低于门槛即红，涨出门槛 1 个百分点以上打 `RAISE` 提示，让门禁自己催着往上抬。取整数是有意的：账面最多落后实测不到 1 个点，换掉 Node 版本的浮点漂移不会误报；需要更严时把实测值原样写进清单。
- **豁免必须写具体理由，且反向校验**：单测 import 不到的文件登记进 `unmeasured`（React 组件、CSS 模板、依赖宿主模块表的适配层各自说明）；登记了却出现在报告里同样红，否则豁免清单会变成「什么都不测也绿」的垃圾桶；清单路径必须真实存在。
- **不传自定义 reporter**：`--test-reporter=dot` 不打印覆盖率表格，自定义 reporter 会抑制报告，所以用默认 spec 输出、从 `ℹ` 开头的行里挑表格。
- **接进 `check`，替代裸 `node --test`**：测试只跑一遍，覆盖率插桩在同一遍里完成；子进程经 `scripts/spawn-command.mjs` 起——`scripts/` 不许直接引 `node:child_process`。
- **只判行覆盖**：分支与函数覆盖率既不设门槛也不进门禁输出；行覆盖必要不充分——100% 只证明行被执行过，不证明行为对。
- **不可达分支按死代码删，不为凑覆盖率写走不到该行的测试**：Node 不支持 `/* node:coverage ignore next */`（实测仍计入未覆盖），所以把「未知类型 throw」这类分支改成初始化即抛错的静态映射查表，仍然 Fail Loud。
- **「常量文件测不了」要分开看**：CSS 模板给 `document` 一个桩就能加载到 100%，不该登记成不可加载；真正拿不到的是依赖宿主模块表的文件。

## 边界

- 门禁只判 `src/**/*.js`：`index.js`、`scripts/`、`build/` 不进分母，与宿主只 gate 各包 `src` 同口径。
- 分母完整性只能由入口脚本守：单测判解析、判定与清单自身合法性，「报告里缺了谁」要跑测试才知道。
- 覆盖率与 e2e 是两条证据：登记进 `unmeasured` 不等于该文件被验证过，client 组件行为仍归 `npm run e2e`。
- 客户端组件一旦抽出纯函数、能被单测 import，就该从 `unmeasured` 移进 `thresholds` 或直接 100%，清单过期会被反向校验当场报出。

## 验证

`tests/coverage-gate.test.js` 覆盖表格解析、门槛判定、豁免反向校验与清单自身合法性；双向验证：新增未登记文件、抬门槛、把已测文件登记成不可加载，分别得到 `NONE` / `LOW` / 反向违规并以 1 退出。
