# Agent Note: 项目区块跟随宿主 0.2.2 的行几何

Status: implemented

## Problem

宿主 0.2.2 压低了项目行高度并换了小节标题的左内边距，本仓的项目区块仍照 0.2.1 的数值：行高、行首图标、标题与「工作区」标题四处都对不齐，用户看到「项目、下面的 session、工作区没对齐」。

## Decision

**行几何照宿主当前版本的行声明。** 项目行用与宿主同一组声明：高度、左右透明边框吃掉侧栏绘制内缩、`background-clip: padding-box`，内边距由行内边距变量减去绘制内缩算得。0.2.1 没有这两个变量，会退回「固定内边距、无边框」，正是那版硬编码的几何。会话行右侧内边距改回与宿主一致的取值（此前误按行内边距减绘制内缩来计算），左内侧与宿主相同；hover 底色随边框内缩，不再铺满整行。

**小节标题必须是 header 的第一个内容。** 「工作区」标题从内边距处起排，前置一个图标槽会把「项目」推右十几像素，所以删掉 header 的目录图标槽，收起箭头移到标题之后、仍只在悬停时出现；标题外边距用本区块自己的取值，不跟下方列表抢间距。代价是「项目」标题没有装饰图标——项目行的行首图标仍在，区块识别不受影响，标题对标题的对齐是更显眼的契约。无用的目录字形随之从字形表删除，测试改为断言「标题是 header 的第一个内容、箭头在标签之后、字形表里没有目录字形」。

## Alternatives considered

- **继续用 0.2.1 的硬编码几何**：0.2.2 下行高、图标、标题与「工作区」四处都对不齐；改用宿主同一组声明。
- **加版本探测 / 两套几何分支**：宿主没有暴露行高变量，同一份声明只能对齐一版；靠缺失变量自然退回 0.2.1 形态。
- **保留 header 的目录图标槽**：会把「项目」标题推右十几像素；删掉图标槽，标题对标题对齐。
- **追 header 右边缘的负外边距**：只差几个像素，还要复制一层外扩；不追。

## Consequences

- **0.2.1 上项目行比宿主矮一点**：宿主没有暴露行高的 CSS 变量，同一份声明只能对齐一版；`engines.dsh` 仍允许 0.2.1，这点差异记在已知差异里，不为它加版本探测。代价是 e2e 在 0.2.1 上会红——那是真实差异的正确报警。
- **header 右边缘没追**：宿主用负外边距让最后一枚按钮比内容区再靠右一点，本区块差几个像素；不追，避免为复制这层外扩再加负外边距。
- **收起箭头的位置变了**：从标题前移到标题后，点击标题仍然收起/展开整个列表，交互契约不变；发现路径仍只有悬停。
- 只对齐几何，不改字号、行距、语义色与 hover 行为。

收益：项目行、会话行与小节标题在 0.2.2 上与宿主同一起点、同一行高，视觉不再错位。
