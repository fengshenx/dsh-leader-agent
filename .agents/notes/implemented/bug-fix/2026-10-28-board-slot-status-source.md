# 槽位圆点的状态来源与保留失败的处理

## 背景

用户反馈 Card 上看不到 sub agent 正在 running 的状态（槽位小圆点不亮）：看板所在的侧栏座不提供运行态 hook，运行态只能取自保留会话的快照，而保留失败的两处 `catch` 是空的，绑到裸 uuid 子会话时只留下一个空心虚线圈，没有日志可查。

## 决策

**子代理会话用地址形式保留。** 子会话 id 在客户端会话目录里没有独立条目，`sessions.retain(id)` 认不出来。保留目标先问宿主的 `sessions.subagentAddress(id)`，拿不到就用建卡会话补一个 `mode: 'unknown'` 的地址；模式只影响宿主怎么配置子代理，不影响能否认出会话。

**父会话取卡片自己的 `createdBy`，不猜看板所属会话。** worker 由建卡的会话派出，建卡时已记下 `exec.agent.id`；看板所属会话在跨项目聚合时是错的，用它当父会把地址挂错地方。卡片没记建卡会话时才退回看板所属会话。

**保留失败必须报告，且同一会话只报一次。** 失败条目不写入 `entries`（语义是该槽位状态未知），经 `onError` 报一条带会话 id 与原始错误的日志；`reported` 集合去重，否则每次 `needed` 变化都会重报一遍。

**同步效果的依赖只留 `needed`。** 取值本来就走 `latest` ref，`getSessions` 进依赖没有作用，只会放大重试风暴。

**「等你输入」「未读」两档如实收窄。** 这条路径无从表达就不伪造能表达的来源；文档改成「执行中与上次执行失败成立，等你输入与未读无从表达」。

## 边界

- 「子代理槽位 + 子代理同时在跑」没有同框实测：侧栏把子代理会话隐藏了，从 UI 打不开它去触发运行；两段证据分别覆盖地址回退与快照运行态推亮圆点。
- 绑定一个「宿主认地址、但快照永远不来」的会话时，圆点会长期停在未知档且无日志——保留租约没有超时事件，要覆盖得给保留加计时器，那是一个独立层次。

## 验证

`tests/slot-retain.test.js`：撤掉 `report()` 的去重时报「只报一次」的用例变红，还原后全绿。mock provider 真机下裸 uuid 子会话的圆点从 `unknown` 变 `idle`、正在跑的会话推到 `running`，控制台无失败报告。
