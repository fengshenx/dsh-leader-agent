# 0.2.2 的左栏滚动网格里，项目区块要换落点

## 背景

宿主 0.2.2 把左栏的面板列表与工作区包进同一个滚动网格，`nav` 下沉一层。本仓的项目区块靠 DOM 注入取位：从 footer 锚点向上找「直接子元素含 `nav`」的祖先作为左栏根，判据一路走到 `null`、portal 不生效，内容留在 footer——位置从「工作区之上」掉到「设置按钮之上」，就是用户看到的「项目目录缩到最下面」。

## 决策

**认 `nav`，不认层数。** 左栏根的判据从「直接子元素里有 `nav`」放宽成「子树里有 `nav`」。安全性不来自「`nav` 只出现在左栏」——对话区、设置页也渲染 `<nav>`——而是来自锚点位置：锚在 footer 里，从 footer 到左栏根之间没有别的 `nav`。

**落点按宿主结构分两版。** 0.2.1 把区块插在 `nav` 之后；0.2.2 要插进 `nav` 的下一个兄弟（工作区容器）的顶部。**不能**继续插在 `nav` 之后：新元素会被网格自动摆进第 1 行那格几乎为空的单元格，区块被压成一条竖条，视觉上像贴在面板列表上。两种结构下的视觉顺序都是「面板列表 → 项目 → 工作区」；找不到落点就退回 footer 锚点渲染，降级路径保留。

## 边界

- 只覆盖宿主这两版结构，不写通用选择器。0.2.2 分支把 `nav` 的下一个兄弟当工作区容器、没有独立校验：宿主将来在两者之间再插元素，容器会跟着插进去。e2e 兜底的是「区块没退回 footer、宽度没被压扁、在 `nav` 之后」，不是「任何结构下都插对」。
- 0.2.2 起区块与面板列表、工作区一起滚动（宿主把这整块做成滚动区），不再像 0.2.1 那样固定在栏中；不为此加 `position: sticky` 之类的额外样式。
- 不新增槽位、不改宿主 DOM 结构、不依赖哈希类名。锚点只在挂载时找一次；宿主运行中替换左栏根节点时需要重挂（当前不这么做）。
- 长期要靠宿主提供位于工作区之上、与它并列的 list slot；DOM 取位只是过渡，缺口见 [capability-gaps 第 27 条](../../../../docs/capability-gaps.md)。

## 验证

`tests/e2e/project-placement.e2e.js`：把落点换成朴素「插到 `nav` 之后」时断言红（`hostParentIsExpected=false`），把左栏根判据精确还原成「直接子元素含 `nav`」时断言红（`hostFound=false`、`inFooter=true`）；还原后绿。
