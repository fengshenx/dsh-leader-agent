# 换新 Leader 后的落点与官方折叠计数

## 背景

两处用户可见缺陷：换新 Leader 后新会话「闪一下就没」——新会话先挂进工作区被宿主树渲染，而它属于排除集，渲染层要等项目摘要刷新后才知道新 id；官方「展开其余 N 个会话」的 N 含被隐藏的项目会话——折叠按数据层算，排除了行却不排除计数，全部会话被排除时还留下一颗点了没反应的按钮。（项目自 2026-11-03 起不再挂工作区，闪烁路径已消失；落点顺序的决策保留。）

## 决策

**换新 Leader 先写回摘要、再打开新会话。** 远程响应带回新 `leaderSessionId` 后先写进本地项目摘要，让新 id 立刻进排除集，不必等刷新回来；再导航打开它。打开是这件事唯一的回执——新 leader 不在项目树下单独出行、官方树里又被排除，不导航过去用户只能靠猜。

**折叠数字在渲染层按分组修正，判据是「宿主口径减去该组未被渲染的排除行」**：真实剩余 = 宿主 N −（该组排除集大小 − 该组已渲染且隐藏的行数）。排除集大小由工作区快照与归档集合算出，归档的会话宿主自己不渲染、不计入；已渲染隐藏行按「向上第一个带展开按钮的祖先」归组，子工作区的行不能算到父组；真实剩余为 0 时藏掉按钮。

**改写的文案要能认出自己。** 宿主原文案与我们写的那句分开记在 `data-*` 上，靠「当前文本是否等于我们写的那句」区分来源，否则会把改过的数字当宿主口径再减一次，数字一路往下掉。观察器要补 `characterData`（React 重写按钮文本走的是文本节点），卸载时把文案还原成宿主口径，插件重载而页面不刷新时不留少掉的数字。

**界面文案统一为「换新 Leader」**：按钮 title、菜单项、提示条、看板指路文案与文档引用一起改；代码注释里的动作描述保持原样。

## 边界

- **点击步长改不了**：宿主每点一次展开加固定几条（最后一次放完），文案减的是真实剩余，所以一次点击新增的可见行可能少于数字变化量。彻底对齐需要宿主支持按外部集合过滤会话（见 [capability-gaps 第 29 条](../../../../docs/capability-gaps.md)）。
- 只修真实工作区分组；「未分组」桶里的项目会话不改按钮——那个桶没有 workspaceId 可对应。
- 闪烁只能缩短、不能根除：建会话到响应到达客户端这一段仍在宿主手里。

## 验证

`tests/workspace-exclusion.test.js`：注释掉折叠数字修正的调用时计数用例变红，还原后全绿。`npm run e2e` 的真实宿主挂载冒烟通过，页内无 console 错误。
