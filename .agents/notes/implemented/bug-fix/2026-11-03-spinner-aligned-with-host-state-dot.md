# Agent Note: 运行中加载圈改用宿主 StateDot

Status: implemented

## Problem

项目行与会话行的运行中指示各有一个自绘 span（边框缺口环 + 快速旋转），和宿主自己的加载器在转速、形状与相位上都不是一套：小尺寸下边框环被抗锯齿磨得不像正圆，多个圈各转各的，也没处理「减少动态效果」偏好。

## Decision

**两处渲染都改用宿主基线模块的 `StateDot`（`state: 'ongoing'`），删掉自绘样式与关键帧。** 组件走 `@deepseek-ai/dsh-client-ui-primitives`，与 Markdown 渲染同一条基线路径：留在产物外、运行时同一实例，`engines.dsh` 下限版本已导出。不传尺寸——运行态默认尺寸与官方会话行同一槽位；装饰语义由组件自带 `aria-hidden`，不再手写。全仓不再有第二套加载圈。

**行首槽位容器要成为 flex 容器。** 换成 SVG 后暴露出既有的布局缺口：这层 span 没有布局规则，SVG 按行盒基线排，槽位被撑高、圈比行中心偏高。补 `display: inline-flex` 与居中后，圈与目录图标都以行中心对齐，运行态与空闲态切换零跳动。

## Alternatives considered

- **保留自绘 span / 自写关键帧**：转速、形状、相位都与宿主不一致，也没处理「减少动态效果」；改用基线 `StateDot`。
- **照抄宿主的 CSS 动画**：仍是第二套实现，宿主改版就要同步；复用冻结模块表里的组件。
- **给 `StateDot` 传尺寸或继承 `currentColor`**：宿主组件固定三级标签灰，项目行激活色不再由加载圈承担；这是与宿主一致的代价。

## Consequences

- **项目行加载圈不再跟随激活色**：自绘版用 `currentColor` 继承槽位色，`StateDot` 固定三级标签灰。这是「和宿主一致」的代价——宿主自己的会话行也是这个灰；组内激活态仍由文件夹图标承担。
- 只覆盖运行中，不覆盖待输入 / 已完成 / 空闲：其余状态宿主自己的行有。
- 加载圈尺寸统一到宿主默认值，行高不变；行首图标随槽位改 flex 一并落到行中心，视觉位置比旧版略低，是对齐修正而非新样式。
- 未做「真实运行中」的真机视觉取证：造这个态要会话正在请求模型或执行工具，隔离实例里需要真实模型或按 session 分游标的 mock（见 `docs/e2e-testing.md`）。

收益：两处运行中指示与宿主同一套组件与节奏，小尺寸下不再出现歪圆与各转各的。

## Testing

`tests/project-panel.test.js` 的接线守卫钉住两处 `createElement(StateDot, { state: 'ongoing' })`，并断言自绘类名、关键帧与旧的状态属性都不再出现：把任一渲染改回自绘 span 时「协调者运行态接线到行首加载圈」变红，还原后全绿。
