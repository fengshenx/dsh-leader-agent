# 未分组组头改按会话快照判空，不再读 DOM

## 背景

用户报告：删掉项目目录或工作区后会话「消失」，卸载插件「未分组」就回来。上一次修复仍按 DOM 判空——从组头往上找分组容器、数容器里的会话行；这条判据把正确性押在宿主的排版上，一旦容器里查不到行就无条件给组头加隐藏类，整组消失。

## 决策

**判据搬到会话快照。** `shouldHideUngroupedHeader` 只问一件事：未分组里剩下的会话是不是全在排除集里。答案只取决于会话 id 与工作区归属，既不读 DOM，也不复刻宿主的可见性口径；宿主换一版渲染实现都不会让它失效。

**失败方向固定成多显示。** 快照还没到、组里一条会话都没有、或组里还有空会话时都不藏；只有 subagent 与已归档不参与判定（这两类宿主一定不渲染它们的行）。DOM 上只留一条保护：还有可见的「展开其余 N 个会话」就不藏。宁可留一个空组头，也不误伤用户自己的会话。

**折叠按钮的数字修正与组头判据分开。** 前者仍按宿主可见性口径算——它要跟宿主的折叠数字对齐，而组头判据要保证不误藏。

**项目列表加低频轮询。** 目录可用性原本只在刷新时算，而刷新只发生在挂载、通道就绪、窗口聚焦与增删改之后；用户在文件管理器里删目录既不产生会话事件也不产生焦点事件，排除集会一直停在「目录可用」。改成每 5 秒重读一次项目列表，页面不可见时跳过、切回可见立刻补一次；刷新时用 `sameProjectList` 比较渲染字段，值没变就不重渲染也不广播。

**不在渲染层复刻宿主的渲染时机与可见性过滤。** 折叠、虚拟滚动、分组顺序都是宿主的实现细节，换一版就要重新对一次；「剩下的会话是否都在排除集里」与它们无关。

## 边界

- 快照计数依赖会话行与工作区列表的新鲜度：宿主缓存旧值时组头会按旧值显隐一帧。
- 目录状态最坏滞后一个轮询间隔，页面不可见时更久。
- 会话能否「落到未分组」仍由宿主决定（删工作区只删注册，会话记录保留）；本仓只管不把它们藏掉。

## 验证

`tests/workspace-exclusion.test.js` 与 `tests/project-panel.test.js` 钉住判据与项目列表的等价判定；`tests/e2e/ungrouped-header.e2e.js` 在判据恒返回「藏」时变红（断言读到 `true !== false`），还原后绿。`tests/e2e/project-directory-gone.e2e.js` 去掉手工派发的 `focus` 后仍通过；把轮询间隔调大后同一条用例超时变红。
