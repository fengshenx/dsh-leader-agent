# 协调者工具面的裁剪时序

## 背景

新建项目的协调者会话拿不到 `spawn_worker` / `message_worker` / `list_cards`——工具面被裁成普通会话档，项目建出来是空的。原因是工具面在 `agent/created` 上按 `isCoordinatorSession()` 当场裁，而建会话内部就发这个事件，当时会话身份还没登记进注册表；裁错的限制也不会自己松开，要等会话下次冷恢复才重裁。

## 决策

**会话 id 由我们预先生成，身份先登记，再让宿主用这个 id 建会话。** `sessionController.create({ sessionId })` 与 `agents.create({ sessionId })` 都接受调用方指定的 id，所以建协调者会话时先生成 id、往注册表写一条占位，再调建会话实现，最后补上项目 id。

**登记条目先只写目录，`projectId` 事后补。** 项目 id 要等存储写入返回才有值；占位期间没有项目记录指向这个会话，解析时退回 cwd 判定。

**建会话失败或 id 不一致时撤掉占位。** 失败路径不留半条记录；id 不一致说明建会话实现没按契约用传入 id，当场抛错而不是留一个工具面残缺的协调者。

**换新协调者走同一条「预生成 + 先登记」的路径。** 新会话出生即协调者；旧会话的索引条目仍等改绑成功后才删，改绑失败时旧身份保持不变。

**不在建会话后回收限制再重裁，也不反转成先落项目记录再建会话。** 前者要保存 disposer、找回 agent，还得赌重裁发生在首轮请求组装之前；后者除了预生成 id 之外无解，而预生成之后先登记索引已经够了。

## 边界

- **已裁错的会话不会自动修复**：修复前建的项目，协调者工具面仍是普通会话档；重启实例让它冷恢复一次即可，不必重建项目。
- **依赖宿主尊重传入的 id**：`engines.dsh` 上限是 `<0.3.0`，0.2.x 两条路径都用调用方 id；真变了会走「id 不一致」抛错路径，建项目直接失败并说明原因。
- **索引未就绪的宽松放行不变**：索引重建失败时仍对任何会话返回 true，保证协调者首轮有工具；派工这类高危操作另走索引就绪判定。本决策只让正常路径不再依赖它兜底。

## 验证

`tests/projects-service.test.js`：把 helper 改回「先建会话后登记」时「建协调者会话那一刻，注册表里已经有它」变红，删掉换协调者失败路径的占位清理时「改绑失败也撤掉占位」变红；还原后全绿。
