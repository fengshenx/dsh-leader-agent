# Agent Note: 项目删除合并为一个入口

Status: implemented

## Problem

项目行的「更多」菜单原有两条破坏性入口：「从 dsh 移除工作区」（只删宿主工作区注册）与「注销项目」（只删项目记录）。两者都不完整：前者删完下次打开项目会自动重建；后者删完，插件注册的工作区变成没人认领的孤儿。想让一个项目彻底消失，得连着点两次。

## Decision

**合成一条「删除」**：删项目记录 + 移除插件为它注册的工作区，复用 dsh 自己「删除工作区」的语义与措辞——文件夹与会话记录都保留，其会话显示在工作区树的「未分组」下。

- **先移除工作区、再删记录**：反过来时中途失败会留下一个谁都不记得的孤儿工作区。
- **只删插件自己注册的工作区**：`workspaceId` 只记插件建的那个（复用的用户工作区不记，见[项目作用域与角色槽位](../architecture/2026-10-23-project-scope-and-role-slots.md)）；没有 `workspaceId` 的项目只删记录。
- **宿主工作区服务不支持删除时仍然删项目**，原因带回客户端显示——这条退路等于旧的「注销项目」，用户仍可在官方工作区面板手动删。
- **远程方法叫 `deleteProject`**，不叫 `remove`：`remove` 撞的是 `RemoteNamespaceService.prototype.remove(kind, method, token)`，整个命名空间会被拒收；它也不是 Cordis 服务原型的成员（capability-gaps 第 28 条）。wire 契约里 `unregister` / `removeWorkspace` 一起删掉，不保留旧方法。
- **二次确认**沿用 `confirm-dialog.js`，文案按项目有没有插件工作区分两支：有工作区才讲「从 dsh 工作区列表移除」与「未分组」，否则只讲删项目。
- **菜单不留「打开协调者会话」**：点项目行本身就会打开，菜单只放行点击之外的动作。
- **「无需移除」与「移除失败」分开报**：没有工作区服务、项目没有插件注册的工作区、工作区已不在宿主里，这三种都报 `skipped` 且不带 `reason`；`reason` 只留给真失败，否则正常删除会被渲染成「工作区未移除」的警告。
- **重复删除按幂等成功收尾**：对不存在的项目返回 `notFound`，客户端关弹窗、刷新列表、只给一句「已删除项目」，不让弹窗卡死。

## Alternatives considered

- **保留「移除工作区」与「注销项目」两条入口**：两者都不完整，彻底消失要点两次；合成一条「删除」。
- **先删项目记录、再移除工作区**：中途失败会留下谁都不记得的孤儿工作区；反过来先移工作区。
- **删除所有工作区，包括用户复用的**：`workspaceId` 只记插件建的那个；用户工作区不碰。
- **宿主不支持删工作区时连项目也不删**：退路等于旧的「注销项目」；仍删记录并带回原因。
- **远程方法叫 `remove`**：撞 `RemoteNamespaceService.prototype.remove(kind, method, token)`，整个命名空间会被拒收；叫 `deleteProject`。

## Consequences

- 删除工作区会带走用户在它下面手工开的会话的归属：会话日志保留，但落到「未分组」，不再按目录分组——这是 dsh 自己的删除语义。
- 卡片不级联删除：项目没了就无法再从看板进入它。
- 协调者会话保留，只变回普通会话。
- worker 常驻会话也不停：dispose 会掐掉正在执行的活，与「删项目不等于杀会话」冲突，是否级联是产品决策，本轮不做。

收益：项目彻底消失只点一次，工作区与项目记录按安全顺序一起收，失败与幂等都有明确回执。

## Testing

`tests/project-delete-notice.test.js` 覆盖「真实 service → remote → 提示文案」的组合；双向读数：撤掉 `removeWorkspace` 调用 → 「删除项目一并移除插件注册的工作区」与「不碰复用的用户工作区」变红，删掉 `notFound` 分支 → 「重复删除按幂等成功收尾」变红，还原后全绿。
