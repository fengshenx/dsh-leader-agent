# 项目树里被打开的 worker 会话有自己的选中态

## 背景

点开项目树里的 worker 会话后，主区域切过去了，但左栏看起来「焦点还停在项目上」：项目行整行铺着底色，被点的那条会话行没有任何标记。宿主工作区树是两层语义——分组文件夹图标点亮、会话行铺整行底色，本仓只实现了第一层。

## 决策

### 选中态分两层，照宿主工作区树

- **整行底色只给协调者会话**：`isCoordinatorCurrent`（当前会话是现任协调者且未归档）。协调者在项目树下不单独出行，项目行就是它的入口，这条底色是唯一的位置回执。
- **项目行的「组内有当前会话」降为文件夹点亮**：`isProjectCurrent()` 判据不变，用途从整行底色改成给行首文件夹上色（`data-active`）。
- **会话行新增 `data-selected` / `aria-current="page"`**：当前会话等于行 id 时铺与 hover 同款的整行底色。
- **两层不同时铺整行底色**：整行底色的语义是「你现在看的就是这一行」，worker 是项目下另一行；同时铺会看成选了两个，分不清哪一行是主区域的正主。
- **保留项目行的激活态**：会话行可能被水位折叠或项目本身收起，这时唯一能说明「你在看这一组」的就是文件夹图标。

### 协调者运行中：行首目录图标换成加载圈

- 协调者跑起来时行首槽位换成加载圈，`isCoordinatorRunning` 只认现任协调者；worker 在跑不影响项目行，它们各自的行上有自己的加载圈。理由同上一节：协调者在项目树下不单独出行，项目收起或 worker 行被折叠时，行首是唯一能看出「它还在干活」的位置。
- 加载圈画在行首槽位内部、不替换容器：激活色挂在容器的 `color` 上，容器被顶掉会同时丢掉「本组有当前会话」与收起态的活动提示。hover 时整个槽位让位给展开箭头，加载圈跟着收起。

> **已被 [2026-11-03 加载圈改用宿主 StateDot](../bug-fix/2026-11-03-spinner-aligned-with-host-state-dot.md) 取代**：加载圈现在是宿主基线模块的 `StateDot`（`state: 'ongoing'`），颜色固定 `label-tertiary`，不再用 `currentColor`；「画在槽位内部、hover 让位」这两条仍然成立。

### 运行态合成归 activity-indicator

- 协调者与 worker 的活动提示合成在 `showsProjectActivity`，取舍与验证见 [项目行收起时的运行中指示](2026-11-02-project-activity-indicator.md)。

## 边界

- 项目收起时不自动展开到当前 worker 行：展开状态归用户，自动展开会在每次切会话时重排左栏。
- 键盘可达性没变：`SessionRow` 仍是 `div`，没有 `tabIndex`，Tab 键到不了。这是既有缺口，不在本次范围。
- hover 时行首文件夹被换成展开箭头（既有行为），此时看不到文件夹的激活色，箭头也不跟着亮。
- 运行态读会话行的 `running`：会话列表还没同步回来、或协调者已不在索引里时按未运行处理，下一帧订阅刷新补上；项目行不自己轮询宿主。
- 当前会话若是项目工作区里用户手动开的会话（不属于项目），两层都不亮。

## 验证

`tests/project-panel.test.js`。双向：删掉 `isCoordinatorCurrent()` 的协调者判据 → 整行选中用例红；删掉 `SessionRow` 里的 `data-selected` → 接线守卫红；还原后全绿。会话行的接线（`selected` → 两个属性）由源码断言守着——仓里没有 jsdom，`SessionRow` 渲染不出可断言的元素。
