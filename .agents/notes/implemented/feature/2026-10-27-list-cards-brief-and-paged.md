# Agent Note: 查卡工具的列表摘要与分页口径

Status: implemented

## Problem

项目卡累积后，`list_cards` 的全量输出从约 3,160 字符涨到 98,652 字符，检查点 JSON 占七成；旧列表不渲染 links，模型把「没渲染」读成「字段为空」，于是误判项目卡没有产物链接（实际 130/134 张都有）。

## Decision

- **模型出口与客户端出口分离**：工具 `execute` 返回全量卡片加解析后的 `query`，分页与状态过滤只发生在 `output.render` 给模型的文本上；`output.presentationMeta` 始终投全量。客户端的唯一取数通道就是 `presentationMeta`，被裁掉就是丢卡；而它是同步函数、拿不到 store，过滤只能落在 `render` 上。
- **默认只列 `active`**：`status` 枚举扩为 `active | done | archived | all`，删掉 `includeArchived`（未发布，不留重复参数）。这是可见行为变更：协调者默认看不到已完成卡，要看得显式传 `status: 'done'`。
- **列表只渲染可观测事实**：每张卡一行标题（含编号、状态、cardId、revision、更新时间）加三条存在性标记（`spec` / `links` / `checkpoint` 的有无）与槽位行；规格与检查点全文只在传 `cardId` 的单卡查询里出现；链接只给标签（至多 5 个、单个至多 32 字符），地址与用途留给单卡查询。
- **存在性标记无条件成行**：省略「有/无」会被模型读成「没有」；空集合显式写「无」，与「未渲染」区分开。
- **`revision` 在列表里可见**：协调者的工作流是「查卡读 revision → 改卡带 `expectedRevision`」，不显示这条工作流就断了。
- **输出有 6000 字符预算**：逐卡累加，超出按卡片边界截断并给续页位置；没到预算但本页没放完时同样给续页位置。截断不切半张卡。
- **首行只报「共 N 张」**，本页显示几张由尾注说。首行若按 `limit` 写「本页 20 张」，预算截断后会与尾注自相矛盾，模型不知道信哪个。
- **空页与翻过头是两句话**：一句是事实（各状态共几张），一句是操作提示（从 offset=0 重翻）。混成一句会让协调者以为卡被删了。
- **参数非法直接报错**：状态不在枚举、`limit` 非正整数、`offset` 为负、`cardId` 为空串都抛错；`limit` 超过 100 收敛到 100——要一页看更多是合理请求，只是有上限。

## Alternatives considered

- **保留全量输出**：项目卡累积后到 98k 字符，检查点 JSON 占七成，模型读不完；改为摘要 + 分页。
- **在 `presentationMeta` 里分页/过滤**：客户端唯一取数通道，被裁掉就是丢卡；分页只落在 `render`。
- **保留 `includeArchived` 或省略「无」标记**：重复参数会被误用，省略存在性会被模型读成「没有」；显式成行。
- **首行写「本页 N 张」**：预算截断后与尾注矛盾；首行只报总数，页数放尾注。

## Consequences

- `presentationMeta` 投全量，不受 `status` / `limit` / `offset` 影响：看板是全量视图，分页只给模型看。
- 列表按 `updatedAt` 倒序，不按编号：正在动的卡不能被历史卡挤出第一页。
- 单卡查询忽略 `status` 与分页参数；`cardId` 与冲突的 `status` 同传时按 `cardId` 查——单卡要给事实，不能因状态过滤说「卡不存在」。
- **首张卡无条件渲染**：预算只拦第二张往后，极端情况下输出会超上限。宁可超预算也要给第一张，否则模型无法判断项目里有没有卡。
- 槽位行只渲染卡片自己声明的绑定；工具侧拿不到宿主运行态，所以不显示信号灯档位。

收益：`list_cards` 的输出从近 10 万字符压到可读规模，模型能看到链接/检查点是否存在，又不会丢卡。

## Testing

`tests/card-list-view.test.js` 钉住参数、预算、两种空页文案与首行口径；真机读数：模型侧首行只写「共 N 张」，本页张数只在尾注出现，两者不再打架。
