# 新项目的引导卡改为「先讲用法、再问是否初始化」

## 背景

引导卡的动作是替用户发一句开场请求，但新项目没有 `LEADER.md`，leader 会话的提示词里没有任何项目身份，模型只能按宿主默认人格回答——用户点「让它介绍一下自己」，实际收到的是 DeepSeek Harness 的自我介绍。

## 决策

- **用户消息只发一句触发语**（「这个项目还没配置，先讲讲 dsh-leader-agent 怎么用。」），作答要求（先解释怎么工作、再问是否初始化两份手册、确认前不写文件）走运行时上下文：`renderInitializationHint` 在 `LEADER.md` 缺失时取代手册正文，并限定触发面——用户直接派活时不打断、问过没答不重复追问。
- **选注入而不是把长文本塞进消息**：用户消息是对话的一部分，几百字的「你是这个项目的 leader」以用户口吻出现像自言自语；注入项每轮求值、文本变化才追加一份新快照，手册建好后提示自动消失，不需要额外的「已提示过」状态。文件读失败（EISDIR、EACCES）仍返回空串——那不是「没初始化」，提示用户去建一个已经存在的文件只会误导。
- **三种「没手册」分开说**：文件不存在、文件存在但只有空白、旧名手册有内容。前两种问的是不同的事（建文件 / 补内容），混成一句会让模型对着一个已经存在的空文件说「还没有」，甚至重复创建；第三种不该问——`loadLeaderManual` 会回落到旧名正文，hint 里再显式判一次，保证两个函数各自独立调用时不会给出相反结论。
- **空白的新版不遮蔽旧名手册**：`LEADER.md` 只有空白、`COORDINATOR.md` 有内容时，回落到旧名正文并记一条日志。空文件不是手册，让它遮蔽旧名等于「升级到空 `LEADER.md` 就静默失去注入」；两版都有内容时仍以新版为准（内容不一致另报一条）。
- **拒绝不做持久化**：提示词要求模型本轮及本会话不再追问，并明确不要为记录拒绝写任何文件；换新会话仍会再问，彻底停用靠创建 `LEADER.md`。两个持久化方案都被否决——写进项目目录会污染用户的 git 仓库（插件无权替用户立 `.gitignore`），写进 dsh 数据域在默认 `workspace-write` 沙箱下会被拒、升权还要为一个「别再问」的标记弹一次审批，且失败静默不可见。
- **默认槽位从三角色改为两角色**：`DEFAULT_SLOT_NAMES` 去掉 `discuss`，只留 `dev` / `review`——需求讨论是 leader 派工前自己做的判断，不值得占一个执行者槽位。只影响零合法槽位时的回落：显式 `## discuss` 照常解析注入，内置翻译也保留。
- **骨架随包分发**，放在 `init-leader-agent` skill 的 `references/`（`LEADER.md` 与 `SLOTS.md`），随 `.agents/skills/**` 进包、不用改 `files`；模型拿到 `resourceBase` 直接读。否决新增 `read_manual_template` 工具——它只为递两段静态文本，却给每个会话的工具面永久加一项，而初始化是一次性动作，skill 的按需加载才是对的载体。
- **不自动写文件**：插件不在项目注册时写任何文件；用户确认后由 skill 写，先把 `AGENTS.md` 的受管区块并入，再按项目实际改写两份手册。目录为空就写带 TODO 的骨架，并把还缺的三个问题（项目做什么、什么算交付、有哪些硬约束）问清楚——比生成一份看起来完整、实际是通用道理的 `LEADER.md` 有用。
- **skill 从 `init-project` 改名 `init-leader-agent`**：旧名太通用，容易和其他插件的同名 skill 撞。它是 bundled provider，不落 `~/.dsh/skills`，项目内同名副本仍优先；改名只影响模型发现，不影响已写入项目的文件。

## 边界

- 初始化提示只在「`LEADER.md` 不存在或只有空白，且 `COORDINATOR.md` 也没有正文」时注入；项目已有手册（任一文件名）就不再出现。空白与缺失的文案不同：前者让模型补内容，后者才让它建文件。
- **清空新版 `LEADER.md` 会让旧名手册「复活」**：回落在判定顺序上就是把空的新版当没有，`COORDINATOR.md` 的正文会重新进入注入；想彻底停用就删掉两个文件。
- 提示不打断正常派工：用户直接下任务时模型按常规流程干活，不主动兜售初始化。
- 拒绝只在本会话生效，新会话会再问一次（`docs/limitations.md` 有同一条）。
- 引导卡的 `blank` 判据不变：消息发出后卡片消失，关闭状态按 leader 会话 id 存 localStorage。
- 空目录的骨架带 `TODO`，是给人填的；skill 明确不要用通用道理填满。

## 验证

`tests/leader-context.test.js`、`tests/guide-card-logic.test.js` 与 `tests/slots.test.js`。双向：把「空白/缺失」判定改回只说「还没有」→ 仅空白用例红；让空的新版遮蔽旧名 → 回落用例红。还原后全绿。
