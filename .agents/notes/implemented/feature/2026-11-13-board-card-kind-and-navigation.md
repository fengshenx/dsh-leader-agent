# Agent Note: 卡面按导航目标组织轻量入口，并支持分类

Status: implemented

## 背景

对齐 Telov 的 [PR #1113](https://github.com/fengshenx/Telov/pull/1113)：卡面头部原来的「信号灯 + 编号 + 标题 + 停滞时长」把可读的标题挤在四件东西之间，链接胶囊与会话芯片又是两套容器，真正可点的入口反而最不显眼。同次要求补上任务分类（`kind`）——分类已在卡面参考实现里，是任务流的短标签，本仓此前没有这个字段。

卡面参考实现用 Tailwind 与 Electron 自有主题；本仓是 dsh 插件，样式只能自注入 CSS 并消费宿主 `--dsw-*` 语义令牌（`docs/web-styling.zh.md` 是宿主侧的权威规则）。因此「交互与信息层级照搬、材质与令牌走宿主」是本次的边界。

## 决策

**头部只放只读身份与主信号**。左侧 `#编号 / 分类`，右侧信号灯；标题独占一行，与链接、会话共用卡面左缘。分类是纯文本，不加填充块、圆角或图标——宿主设计系统的显式规则是「只读元信息用纯文本，可点行动才用容器」（`docs/web-styling.zh.md` 的组件规则），而填充块会被读成按钮。分类与编号同用 11px `--dsw-alias-label-caption`，`/` 只做语义分隔。

**链接去壳，保留宿主可点链接示能**。删掉发丝线圆角壳与 22px 缩进，留 `--dsw-alias-link` 色、500 字重、hover/焦点点状下划线。下划线偏移取宿主规范的 3px（不再是旧 chip 为避开底边框定下的 1px）；收起态链接行是裁切带，给容器补 1px 下内边距承接下划线。链接统一 `link-outline` 图标，不再猜测 MR / Issue 类型——标签与目标类型都可自由定义，卡面不需要这项猜测。

**「+N」就地展开/收起**。旧实现点「+N」打开详情，入口位置（链接行）与导航目标（整卡详情）不一致，用户也无法在上下文里比较剩余链接。展开态换行、不再测量；`aria-expanded` 标出开关状态，收起后回到按实测宽度排布。

**会话入口全部直出**。每项只有状态点、角色名与 hover/焦点时出现的方向箭头；行间 4px、列间 12px，自然换行，不收进「+N」——角色数会增长，等宽按钮矩阵在窄栏里会变成按钮墙。只渲染已绑定会话的角色：没有会话可打开的角色不占位，未派工由卡面信号灯的「无信号 / 未派工」承担。

**停滞只由空心灯表达**。卡面删除「停滞 Xd」文案；`attention` 混合态仍保留红实心（失败比停着更该先看），其余档位的停滞把实心换成 1px 状态色描边。形状变化只换填充，色相不动（`--dsh-leader-agent-signal-tone` 同时供实心与空心取用）。与 `unknown` / `none` 的虚线区分：停滞是确定的空闲，不是不可知。代价是卡面不再给出「停了多久」，与参考实现经用户裁决后的结果一致。

**分类进数据模型但不进排序**。`kind` 可选、最长 24 字符、不能换行；`update_card` 传空串清除，建卡时空串与省略同义。判据只有一条：非空字符串才显示，非字符串与纯空白都按未分类（`board-projection.js` 的 `cardKind`，卡面与详情浮层共用）。worker 不能改分类——那是 leader 对任务流的归类，与规格、标题同档。`list_cards` 每张卡显式列出分类（没有时写「无」），否则模型会把「未渲染」读成「工具不给分类」。

## 边界

- **分类不参与排序、过滤或看板分组**：本次只做卡面展示与写入通道。需要「按分类筛卡」时要改用 `list_cards` 的查询参数，属于独立议题。
- **不复刻参考实现的卡面材质**：本仓 active 卡已用宿主行内卡片材质（`--dsw-alias-bg-layer-2` + elevation 发丝描边），done 卡仍是无材质的透明行——成品不抢注意力，与 active 卡的材质差本身就是分组信号。宿主规则不允许中性 border 与 elevation 并存，也不允许功能样式表写主题选择器，所以深色可辨度交给主题令牌，不在本仓加 `dark:` 分支。
- **展开态与更多会话会让卡片变高**：这是保留上下文与全部会话状态的代价；默认收起态仍只占一行链接。
- **点「+N」不再打开详情**：无 URL 的引用链接仍打开详情（它没有别处可去），直接链接仍新窗口打开，整卡详情仍由点卡面提供。
- **存量卡没有分类**：不渲染「未分类」占位，也不做数据迁移。

## 验证

- 单测：`npm run check` 1120 通过（17 跳过）；新增用例覆盖 `cardKind` 的五种脏值、`kind` 的建卡/改卡/清除/同值幂等（不递增 revision）/超长/换行/非字符串、worker 改分类被拒且不落盘、`list_cards` 的分类行，以及样式约束（分类无填充/圆角/边框、卡面链接无容器壳、会话行 0.5px 发丝线 + `flex-wrap`）。
- 双向验证（纯函数层）：临时删掉 `normalizeKind` 的换行检查 → 「脏值直接拒收」用例变红；还原后全绿。临时把 `cardKind` 的 `trim` 去掉 → 脏值用例变红（`'   '` 被当成分类）；还原后全绿。
- 浏览器 e2e（`tests/e2e/board-card-kind-navigation.e2e.js`，真实宿主 + 本地 mock，无模型轮次）：种一张有分类、8 条链接（1 条无 URL）、两个槽位（其中 `review` 未绑定）的卡与一张 25 小时未更新的卡，断言头部 `#1/研发`、空槽不占位（会话入口 1 个）、停滞卡信号灯带 `signal-hollow`、卡面正文无「停滞」字样、`+N` 展开后 8 条链接全部直出且开关变「收起」、再点回到收起态。单跑 9.6 秒通过，截图落在 `.dev/e2e-artifacts/board-card-kind-navigation-<pid>/board-cards.png`。
- e2e 双向验证：把「+N」的点击处理改回 `onOpenDetail` → 场景在「溢出开关变成展开态」处 10 秒超时，读数 `aria-expanded=false`；把空槽过滤删掉 → 场景在「会话入口应只有已绑定的 1 个」处变红，读数 `实际 2：["开发","审核"]`；两次还原后均变绿。既有 `board-done-paging.e2e.js` 单跑仍绿（9.6 秒）。
- 全量 `npm run e2e`（串行车道）：新场景与既有 6 条全部通过；`project-workspace.e2e.js` 在一次全量里因「等不到引导卡」失败（读数为 `guideCards: 0`），单跑两次均通过——这一条与本改动无关（引导卡不读卡面），按偶发记录，剩余两条 `session` / `ungrouped-header` 单跑通过。
- 注意：两条 e2e 场景并行跑会互相干扰（都操作左栏项目行），必须按 `npm run e2e` 的串行车道跑。
- 样式表断言：`tests/board-styles.test.js` 守住「只读分类纯文本」「卡面链接无容器壳」「会话行发丝线与换行」「3px 下划线偏移 + 收起态 1px 下沉空间」「链接焦点环内嵌」。
- 文档：`docs/usage.md` 的卡片与看板两节同步分类写入与卡面交互，`docs/architecture.md` 的 worker 写卡范围补上 `kind`；`docs/usage.md` 天花板按当前值从 5800 抬到 6000（余量 5.4%），因为新增了分类写入与卡面交互两处使用者可见的描述。
