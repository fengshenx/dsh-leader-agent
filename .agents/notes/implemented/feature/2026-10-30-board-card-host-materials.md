# 看板卡面改用宿主卡片材质

## 背景

上一版卡面是「无边框无阴影、静态零装饰、hover 只出背景」：卡与卡之间只有一条窄缝、卡面与右栏背景同色，读完一段不知道它到哪结束。用户第二次指认「Card 的样式设计还是丑」，要求复用 dsh 自己的 design token。宿主已有成文的卡片材质与层级规则（圆角 token、发丝描边、elevation、中性 border 与投影不得配对），不需要自己发明数值。

## 决策

> **部分已被 [卡面按导航目标组织轻量入口](2026-11-13-board-card-kind-and-navigation.md) 取代**：链接去壳、静息态降权，chip 的 18px 高 / R4 / 123px 宽 / 1px 下划线偏移随之失效；卡面材质、圆角分档、token 与焦点环规则仍有效。

- **卡面走宿主行内卡片材质**：`bg-layer-2` 底 + `elevation-stroke` 发丝描边；`border: 0`，描边在 `box-shadow` 里，通过重绑 `--dsw-elevation-stroke-color` 换档而不是叠一层真 border。hover 时描边升一档并把投影升到 panel 档。
- **静态描边取 `border-l3`，比宿主成员卡深一档**：成员卡浮在带模糊的菜单面上，看板卡直接在浅色 sidebar 底上独自立着，浅一档在 1x 屏读不出边界。
- **圆角按用途分档**：卡面与骨架取 `radius-lg`（与宿主同形态的多行卡一致）；done 行与折叠开关是单行 cell，取小一档圆角；空态图标底框与宿主同尺寸；右栏 guide 入口保持宿主 `EntryBox` 的档位；链接行不设容器壳，不单独定圆角。
- **成品卡（done）不加材质**：透明行 + hover 出背景，与带卡面的 active 卡靠对比形成主次，而不是靠更浅的描边。
- **卡间距与宿主成员卡栅格同档**：有了描边和投影后，原来的紧凑间距会让相邻两卡的描边挤成一条。
- **编号与时间用 `--dsw-alias-label-caption`，不叠 `opacity`**：alpha 与语义色叠加出来的颜色不属于任何一档 token，换主题时对不上。折叠开关同理用 `label-secondary`，hover 升 `label-primary`。**图形点（信号点、槽位点）是例外**：那里没有更浅的文字档，要的是面积上的退让、不是色相语义，保留 `label-tertiary` + `opacity`；文字类一律换档、图形类允许叠 alpha。
- **链接行用宿主「可点击产物链接」示能**：链接色 + 500 字重 + 默认无下划线 + hover 与键盘焦点同为点状下划线；不套发丝线壳、不加前置图标。下划线偏移取宿主规范；收起态容器补内边距承接下划线。
- **滚动条档位不在这里重绑**：看板渲染在宿主 dockkit 的浮起面里，那层已经把滚动条重绑成 l2 一档，本层再绑是同一个别名的同值重复。
- **焦点环走 `--dsw-focus-ring-*` 与内嵌 offset**：引用这个属性是为了接住指针模态下宿主把它置成 transparent 的抑制；链接行与卡面都内嵌——链接行外层 `overflow: hidden` 会裁掉外扩环，卡面与相邻卡间距很小，外扩环会挤在一起。
- **全圆与胶囊（百分比与超大圆角）配对 `corner-shape: round`**：宿主给所有圆角面套 superellipse，不退出会被压成方角。
- **所有 `:hover` 规则包进 `@media (hover: hover)`**：触屏上 `:hover` 会被点按粘住，这是宿主样式规范的硬要求。

## 边界

- **只保证结构对齐宿主，不保证像素一致**：宿主调圆角、elevation 或色阶时本仓自动跟随；但行列结构、缩进与字号仍是本仓自己的数值。
- **下划线与焦点环的可见性靠真机读数判定**：`overflow: hidden` 会把下划线整条裁掉、把外扩焦点环切成两段竖条，这两个失效模式在 CSS 声明上完全看不出来。1x 屏的发丝线是混合值、更淡——宿主对自己的发丝线是同一取舍。
- **卡面根仍是 `role="button"` 且内嵌可聚焦控件**：ARIA 冲突与上一版一致，本次不动。

## 验证

`tests/board-styles.test.js` 把宿主硬规则固化成结构断言（`corner-shape` 配对、点状下划线、下划线偏移取宿主规范、焦点环内嵌、token 白名单、变体顺序、hover 媒体查询、发丝边框）；双向：把下划线偏移改回旧值，该用例变红。
