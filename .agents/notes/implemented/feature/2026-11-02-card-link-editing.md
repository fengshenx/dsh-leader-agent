# Agent Note: 卡片详情支持编辑链接

Status: implemented

## Problem

看板卡片详情的说明与链接两段都是只读。链接本该归 leader 的 `update_card`，但漏挂、写错、事后补链接都是常态；而看板正是用户看见问题的位置，却只能回会话里让模型改卡。

## Decision

- **写通道只开一条 `updateCardLinks(id, links)`**，挂在既有的项目远程命名空间上，宿主侧转调 `cards.update({ id, links })`，整体替换。不做「加一条 / 删一条」的细粒度方法：列表只有几条，整体替换让并发语义简单（后写者赢），也避免界面与服务各维护一套序号。
- **不传 `expectedRevision`**：浮层里的卡片是打开瞬间的快照，用快照版本号会稳定触发冲突；用户在这里表达的意图就是「这些链接现在是这样」。代价是覆盖同一时刻 leader 的 `links` 变更，这一取舍记在 `docs/architecture.md`。
- **契约形状是「参数名 → 线上类型」**：浏览器侧据此给每个参数选严格 codec，宿主侧只读方法名、形参名逐字对齐契约；新增类型必须登记，未知类型直接抛错，不会静默退化成字符串 codec 到调用时才失败。
- **URL 判定与归一化收在共享模块**：`normalizeHttpUrl(value)` 能解析且 protocol 是 `http:` / `https:` 时返回规范形式 `href`，否则 `null`；`isHttpUrl` 就是它 `!== null`，渲染层与写入层不会对同一个值给出两种口径。三条写入路径都用这一份：浏览器侧编辑态的保存前校验、宿主侧写通道（客户端校验不能当边界，落盘前再跑一遍）、卡片工具（模型是另一个写入者）。
- **选归一化而不是拒绝**：`http:example.com`、`https:/example.com`、内嵌换行的地址在 WHATWG URL 里本来就是合法的 http(s) 绝对地址，拒绝会把能用的地址判死；归一化让落盘值、界面 `href` 与文档口径一致。`javascript:`、`ftp:`、协议相对地址与相对路径仍被拒。
- **工具侧报错必须可执行**：每条带「第几条、哪个标签、收到的原值、该怎么改」，非字符串字段也带类型与收到的值——只说「url 非法」会让模型原地重试。同一处统一 trim、空字段删除、重复 id 换新 id，与看板编辑态口径一致，避免「模型写入的卡在界面上编辑一次就变样」。
- **交互**：编辑入口在「链接」段标题行，只在非归档卡上出现；点开后整段换成编辑器（标签窄、URL 占宽、行尾移除，用途默认收起），底部「+ 添加链接」与「取消 / 保存」。整行都空的新增行保存时丢弃；只填 URL / 用途却漏标签的报错——粘贴 URL 后回车就保存，静默丢行比拦住他更糟。
- **保存成功后回填两处**：宿主返回的卡片同时更新浮层快照与卡面列表，不必关掉重开或等下一轮轮询。合并按 id / revision 判定：在途的轮询响应晚到不会把刚保存的链接打回旧值，保存期间关掉再打开另一张卡也不会被错卡覆盖。浮层这一处抽成纯函数，单测直接锁「A 的保存结果不落到 B」。
- **编辑态的焦点**：进入编辑态落到首个 label（没有链接时落到「+ 添加链接」），取消或保存后回到「编辑链接」；保存期间 `disabled` 会让焦点 blur，失败时把焦点还给提交前的元素。聚焦规则复用 `modal-focus` 的 `pickInitialFocus`。
- **渲染层也认 http(s)**：`isJumpableLink` 要求 http(s)，其余渲染成文字（点它开详情）。写入路径都拦非法 scheme，但存量卡是校验上线前写进去的——那里的 `javascript:` 一旦拼进 `href` 就是注入面，渲染层必须自己守住；相对路径与本地文件链接因此不再可点。

## Alternatives considered

- **链接继续只读、只让 leader 用 `update_card` 改**：用户在看板看到问题却只能回会话里让模型改；开一条整体替换的写通道。
- **做「加一条 / 删一条」细粒度方法**：列表只有几条，细粒度要维护序号与并发语义；整体替换后写者赢。
- **传 `expectedRevision`**：浮层是打开瞬间的快照，版本号稳定触发冲突；这里表达的是「现在就是这些链接」。
- **只接受规范 URL、不归一化**：`http:example.com` 等在 WHATWG 里本来合法，拒绝会把能用的地址判死；归一化后落盘。
- **各写入路径各自校验 URL**：浏览器、宿主写通道与卡片工具会分叉；共享 `normalizeHttpUrl` / `isHttpUrl`。

## Consequences

- **只有 links 可写**：完成、置顶、重命名、删除、改槽位仍归 leader 的卡片工具，卡面也不放操作按钮。
- **存量非 http(s) 链接**：渲染层已把它们降级成不可点击的文字；这类卡打开详情保存时会被拦，要改成 http(s) 或删掉那一行的 url。
- **URL 规则是 http(s) 绝对地址**：`mailto:`、`file:`、内网裸域名会被拒；非规范写法会被归一化后落盘，**不保留用户输入的原貌**——编辑态重开看到的是规范化后的地址。要放宽得同时决定「渲染层哪些 scheme 安全」，不该只改写入侧。
- **跨项目判定不在写通道上**：远程方法是 `direct` 调用，拿不到调用方会话，无法像 `update_card` 那样比对归属；任何能调本机 `/api` 的页面或进程都能按 id 改任意项目的卡。这是单机单用户威胁模型下的取舍；浏览器侧按构造只能看到本项目的卡。
- **详情仍是打开时快照**：别处改卡不会刷新浮层，只有本浮层自己保存的链接会立刻回填。
- **清空是显式意图**：把行删光再保存就是清空链接，不做「至少留一条」的保护。
- **归档卡是终态**：不给入口，卡片库本身也拒改。
- **编辑态的 GUI 未实测**：浮层渲染、增删行、保存回填、错误展示与 IME 回车只有单测与代码阅读证据，留待有可见浏览器面板时补取证。

收益：看板详情能直接编辑链接，URL 口径在界面、写通道与工具三处一致，非法 scheme 不会进 `href`。

## Testing
