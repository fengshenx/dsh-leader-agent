# Agent Note: 看板按项目组织

Status: implemented

## Problem

需求是「一个项目一个看板，不是全局的」与「建卡后直接让右 sidebar 打开看板」。原看板是会话维度的：从当前会话的事件窗口重放 `tool/result` 还原卡片投影，别的会话建的卡看不见，用户还要自己点开右栏 tab。

## Decision

- **数据源换成宿主卡片库**：事件流重放既跨不了会话（worker 建的卡在 worker 的窗口里），又扛不住会话回收（卡片随之消失）；卡片真源本就在 `cards.json`。重放逻辑整段删除，只留不依赖数据来源的信号灯、排序、停滞判定与 chip 排布。
- **归属由宿主按调用方会话判定，模型不传项目参数**：模型未必知道自己在哪个项目的语境里，会话这一侧的事实更可靠。
- **归属判据分两种**：leader 会话走项目注册表里的指针（`leaderSessionId`），这是显式绑定；其它会话按 cwd 与项目目录的 realpath 相同判定——worker 与用户在项目目录里手动开的会话，做的都是这个项目的事。这与项目树刻意不同：树回答「有哪些执行者」，只认 worker 登记表（见[项目树只列 worker 会话](2026-10-27-project-tree-worker-sessions.md)）；卡片回答「有哪些任务」，只认目录一致。
- **归属判定要等索引重建完**：注册表异步落盘，进程内索引是读路径的镜像；重建没完就判会得到「不归属任何项目」，卡片静悄悄地丢归属。
- **编号作用域不变**：全局递增，项目看板按项目过滤会出现空洞，但 `@#n` 不歧义。按项目编号的迁移代价见[卡片存储与编号作用域](../architecture/2026-10-23-card-storage-and-numbering-scope.md)。
- **存量卡片不迁移**：记录里没有创建会话 id，无法可靠反推归属；它们不出现在任何项目看板，但 `list_cards` 的 `scope=all` 仍可见。这是明确的取舍，不是遗漏。
- **跨项目改卡拒绝，无归属的存量卡不拦**：判据是「卡片归属必须等于调用方所在项目」；调用方不在任何项目里同样改不了有归属的卡，否则项目外的会话能改任何项目的卡。没有归属可冲突的存量卡拦下来只会让它永远改不动。
- **自动打开的判据是「新增卡片 id」**，不是内容变化：改一张卡不值得把看板弹到用户面前。
- **监视器跟随屏幕上的会话**：不属于项目的会话没有项目看板可开；用 `sidebarRight.mounted` 拿当前屏幕会话。
- **轮询而非事件订阅**：卡片可能由 worker 建，那边的事件流不在屏幕会话的窗口里；按项目拉一次就能看见。间隔 2 秒，窗口重新获得焦点时立刻刷一次。
- **惰性解析项目 + 下一轮重试**：项目通道的挂载是异步的，第一轮解析失败不该就此放弃。
- **打开前先查已有 tab**：同 kind 的 tab 已存在就 `focus`，没有才 `openTab`，否则每次建卡都会新开一个。

## Alternatives considered

- **继续从当前会话事件窗口重放卡片**：跨不了会话（worker 建的卡在 worker 窗口里），也扛不住会话回收；改读 `cards.json`。
- **让模型传 `projectId`**：模型未必知道自己在哪个项目语境里；由宿主按调用方会话判定。
- **用项目树的 worker 登记表判卡片归属**：树回答「有哪些执行者」，卡片回答「有哪些任务」，只认目录一致。
- **订阅事件而不是轮询**：worker 建的卡事件不在屏幕会话窗口里；2 秒轮询 + 聚焦刷新。

## Consequences

- 没有项目会话的看板是空的，面板显示「当前会话不属于任何项目」与按项目组织的说明。
- 存量卡不进任何项目看板，只能靠 `list_cards` 的 `scope=all` 看到。
- `list_cards` 默认只看本项目（`scope=project`），跨项目要显式传 `scope=all`。
- 看板是 2 秒固定间隔的轮询，不是推送；窗口切走时仍然轮询。
- 卡片归属依赖 cwd：会话不在项目目录里跑，就不属于那个项目。

收益：一个项目一个看板，worker 建的卡也会出现，建卡后自动打开右栏。
