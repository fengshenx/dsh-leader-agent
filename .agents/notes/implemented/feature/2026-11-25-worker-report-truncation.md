# Agent Note: worker 回报的截断标注与分页回看

Status: implemented

## Problem

本笔记取代 [2026-11-03-read-worker-session](2026-11-03-read-worker-session.md) 里的单条 2000 上限、失败原因 200 与 `turns` 窗口语义；身份判据、只读路径与回合折叠形状仍沿用它。

worker 给 leader 的回报有两份文本：完成通知正文（模型读）与界面气泡里的 `report`（人读）。两者原来都是把整段文本 `slice(0, 4000)`：没有截断标记，leader 会把半截产物当成全文；切点可能落在 UTF-16 代理对中间，渲染成 U+FFFD；通知是「整段拼完再切」，产物摘要一长就把「下一步」「换模型重投」这些协议字段一起切掉。

回看侧同样断链：`read_worker_session` 的截断标记只写「原长 N 字符」，不告诉 leader 去哪儿读全文；单条正文上限 2000 比通知的 4000 还紧，出现「通知里看得到、回看反而更短」的倒挂；`turns` 只能取最近 20 个回合，更早的历史没有入口，旧提示只能让 leader 用 `message_worker` 让 worker 重述一遍。

## Decision

- 新增共享函数 `clipText(text, limit, note)`：截断点退到码点边界；标记 `…（已截断，原长 N 码元<note>）` 计入 `limit`；`limit` 小到装不下标记时退化成省略号。截断行为只有这一处实现。上限与「原长」都按 UTF-16 码元计，写「码元」而不是「字符」——3000 个 emoji 是 6000 码元。
- 完成通知先让固定段占住预算：头部（任务、子会话、状态、模型）与尾部（归属提示、下一步、换模型重投）先算长度，只截中间那份产物摘要或失败原因，再用 `clipText` 标注。协议字段不再被内容挤掉。
- 通知正文与气泡 `report` 的截断标记都指向 `read_worker_session`：回报被压短时，下一步是只读回看，不是让 worker 再跑一轮。
- 通知头部里的 worker 名先压到 120 码元：`name` 没有长度约束，不压就会把「状态」「下一步」这些固定段一起挤掉；固定段兜底只压头部、保住尾部协议字段。
- 回合终态的失败说明抽成共享 `describeTurnFailure`：通知与 `read_worker_session` 用同一条文本（`aborted` / `blocked` / `max-tokens` 不再只剩裸 kind），回合级上限与单条正文同值 4000，工具失败原因仍是 200。
- `read_worker_session` 新增 `offset`（跳过最新的 N 个回合，翻页用）：页末按实际展示数给出下一页 `offset`；体积上限丢掉的回合也落在这个偏移上，翻过去能取回。越界（`offset` ≥ 总回合数）报错，不返回空页。
- 单条正文上限 2000 → 4000，与通知的回报上限同值：通知里能看到的那段产物，回看视图装得下，标记的承诺才成立。
- 转录用共享截断函数，提示按成因分开：单条正文超限指向 `offset` 翻页并说明超出部分要让 worker 复述；整页被总量上限挡住时指向下一页 `offset`。

## Alternatives considered

- **只加标记、不加 `offset`**：更早的回合仍然没有入口，标记会指向死路；旧文案「用 message_worker 让 worker 自己复述」多开一轮、多花钱，且 worker 可能已经丢了当时的过程。
- **只把 `offset` 做成字符级偏移**：能读回超长单条，但把「回合」这个既有窗口单位打碎，调用方还要自己算页；单条超限改为让 worker 复述更简单。
- **保持单条上限 2000**：通知能看到 4000 字符的回报，去回看反而只给 2000，截断标记「完整内容用 read_worker_session」就是假承诺。
- **提高或不设通知上限**：worker 写多长都塞进 leader 上下文，会挤掉 leader 自己的工作记忆；4000 是按上下文预算定的硬上限。

## Consequences

- 单条消息超过 4000 字符仍读不全，标记会明说，只能让 worker 复述；这是刻意的上下文预算，不是缺口。
- 翻页是多次工具调用，每页最多 20 个回合；总量上限按页独立计算，读全量历史要多页。`offset` 相对「当前最新」计数而不是游标：翻页期间 worker 新增回合会让页框后移、内容可能重复，最终仍可读全。
- 界面气泡在超长时也会出现截断标记，标记里带工具名 `read_worker_session`——对人来说略像协议文本，但保留了「去哪儿看全文」这条信息。
- 截断标记占用输出预算（约 40–60 字符），极端情况下正文会比上限少几十字符。

收益：leader 收到的回报要么是全文，要么带着「这是截断、原长多少、去哪儿读」三个事实，不会再拿半截结论验收。

- `tests/truncate.test.js`：原样返回、非字符串/空串、非正上限、标记计入上限、装不下标记的退化、代理对与组合字符边界。

- `tests/worker-transcript.test.js`：单条 4000 上限、`offset` 窗口与头部标注、体积溢出给出的下一页 `offset` 确实取回被丢弃的回合；`aborted` / `blocked` / `max-tokens` / `error` 的失败说明进回看。
- `tests/read-worker-tool.test.js`：`offset` 翻页、越界报错、非负整数校验。
