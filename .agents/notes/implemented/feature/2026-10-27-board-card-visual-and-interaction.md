# 看板卡片视觉与交互

## 背景

P2 的看板只有数据通道与一个能列出卡片的壳：卡面是带边框的方框，正文把 `spec` 与 `checkpoint` 全量铺开，没有链接、槽位、信号灯与详情视图。用户指认「Card 的交互完全不对，太难看」，要求重做。宿主侧的差异集中在视觉令牌（`--dsw-*`）、图标（无 sprite → 内联路径）与浮层组件（官方 `Modal` 不可 import → 复制改写）。

## 决策

> 卡面视觉在 P6 被推翻：信息结构（三层 / done 单行 / 信号灯 / chip 排布）保留，材质换成宿主的行内卡片材质，见[看板卡面改用宿主卡片材质](2026-10-30-board-card-host-materials.md)。

> **2026-11-13 起部分被 [卡面按导航目标组织轻量入口并支持分类](2026-11-13-board-card-kind-and-navigation.md) 取代**：停滞时长、链接缩进与胶囊 chip、相对完成时间已删除，标题行加入分类；信号灯、状态双来源、排序、停滞判定与 retain 账本仍有效。

- **卡面零操作铬**：卡片只做信息与导航，完成、置顶、重命名、删除都不放。卡片是协调者维护的事实，UI 越权写会把「谁在改」搅浑；写操作仍归协调者的卡片工具。
- **视觉走「复制宿主数值 + `--dsw-*` 变量」**：不引 Tailwind、不 import 宿主 UI 包；类名统一 `dsh-leader-agent-board-*` 前缀，样式一次注入，沿用确认弹窗「同一页面只注入一次」的做法。
- **信息结构**：active 卡三层（标题行 → 链接行 → 元信息行），done 卡单行轻量变体；卡面无边框无阴影，静态零装饰，hover 只出背景。
- **链接 chip 按实测宽度排布**：可见数量由实测行宽决定，放不下的收进「+N」；测量层是全量 chip 的不可见副本，`ResizeObserver` 监听行宽重排；首帧未测量时全量展示而不是藏链接。chip 间距取 `getComputedStyle` 的真值，JS 不写第二份常量——两份会各改各的。
- **交互三语义**：点卡面其他区域开只读详情浮层；点有 URL 的链接 chip 新标签打开；点槽位 chip 打开该槽位绑定的会话。Enter/Space 只在事件来自卡面根时触发，嵌套控件归自己。
- **卡面根是 `role="button"` 且内嵌可聚焦控件**，严格说违反 ARIA「button 不含可聚焦后代」。这是刻意的取舍：整卡热区与嵌套控件并存，子控件保留独立按钮语义，键盘可达性由子控件保证。
- **信号灯七档**：`waiting` > `attention` > `running` > `unread` > `idle` > `unknown` > `none`，聚合自卡片声明的槽位会话状态，不落存储。未派工与状态未知共用虚线圈：两者都不谎称空闲，形状上与实心档区分。
- **状态有两个来源，合并后成一表**：运行态、等你输入、未读读宿主客户端状态存储 `SessionStatus`（宿主按 `api-session/status` 维护的权威值）；失败原因不在会话状态里，只在快照 `lastAgentError` 里，所以仍要 `retain` 会话 + 订阅快照——`retain` 同时让会话不被宿主回收。快照的 `running` 对未保留的子会话是兜底值，不能据此说「空闲」；状态存储还没建立 `running` 基线时判「状态未知」，不退回兜底值。
- **「等你输入」档当前不亮**：它读 `pendingInteraction`，而宿主没有域发布待处理交互。机制与档位留着，有域发布时自动生效。
- **槽位只渲染卡片实际声明的**：槽位集合由项目 `SLOTS.md` 决定、客户端拿不到，恒渲染空槽等于宣称存在不存在的 worker。未派工的槽位不是按钮——没有会话可打开。
- **排序**：active 按信号档位升序 → `sortOrder` 升序（未设置排后）→ `updatedAt` 降序 → 编号升序；done 按 `doneAt` 倒序；archived 不展示。
- **停滞判定阈值 24 小时**：没有绑定会话（没开始）、名下会话在跑、名下会话状态不可知，三种都不计时——读不到运行态不等于停了，与信号灯「不可知就显示未知」是同一条口径。活动只能用卡片自己的 `updatedAt`；会话列表的 `updatedAt` 是「最后被提示的时间」，拿它当活动度量会把在跑误判成卡住。60 秒计时器驱动判定与相对时长展示。
- **组件的可判定逻辑拆成纯模块**，组件只负责渲染结果：bundle 的运行时依赖只有 Node 内置模块、React 来自宿主，组件本身进不了单测，本仓也不引 jsdom。「Tab 到边缘要绕回」「没有进展就不出现该段」这类规则因此能被直接断言，而不是靠肉眼数 DOM。
- **详情浮层只读、外壳共用**：用 `headless` 模式自带头部（标题就是卡片标题）；`modal-shell.js` 供确认弹窗与详情浮层共用 portal、遮罩、ESC、Tab 焦点陷阱、初始焦点、关闭回焦与宿主 `Modal` 的样式。
- **焦点的抑制与释放整段照抄宿主 `focus.ts`**：只设 `data-dsh-automatic-focus` 属性而不照抄释放逻辑，焦点环就再也回不来，属静默回归。

> **数据源已换**：P5 起看板读宿主卡片库，事件窗口与增量重放整段删除，见[看板按项目组织](2026-10-27-project-bound-board.md)。保留这条只为记录走偏原因：事件窗口跨不了会话（worker 建的卡不在协调者窗口里），也扛不住宿主回收，而卡片真源一直在 `cards.json`。信号灯、排序、停滞判定与 chip 排布不依赖数据来源，原样保留。

## 边界

- **「等你输入」档暂无数据源**：宿主有机制（`pendingInteraction`）但当前没有域发布，这一档不会亮（见 [capability-gaps 第 35 条](../../../../docs/capability-gaps.md)）。
- **详情浮层是打开瞬间的快照、外壳是复制改写**：卡片随后被协调者更新时浮层不刷新，要关掉重开；浮层只读。宿主改 `Modal` 时本仓要同步，与确认弹窗同一条耦合。
- **无 workspace chip**：卡片按项目归属、不按工作区分区，编号全局递增（见[卡片存储与编号作用域](../architecture/2026-10-23-card-storage-and-numbering-scope.md)）。
- **看板会保留槽位会话**：`retain` 的会话在卡片撤掉该槽位后释放，否则状态表会随卡片增删漂移。

## 验证

`tests/board-projection.test.js`、`tests/link-row.test.js`、`tests/modal-focus.test.js`、`tests/card-detail-view.test.js` 钉住档位、排序、停滞、排布与焦点；真机读数：浮层内连按 6 次 Tab 在可聚焦元素间往返、Escape 关闭后焦点回到刚才点的卡面。
