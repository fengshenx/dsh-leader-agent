# 项目行首图标改用宿主应用格子（`apps-add-outline`）

## 背景

项目行首一直是宿主同款的描边文件夹，而这一行是 leader 会话的入口，与左侧宿主工作区树的分组行完全同形——两棵树并排时「项目」和「工作区」只能靠位置区分。

## 决策

- **项目行首固定用宿主 `apps-add-outline` 原样内联，不自绘**：宿主 `ui-primitives` 没有纯九宫格，带格子的只有三格加一个「+」这一族；曾按 16 box 口径自绘九宫格，两轮尺寸调整后仍定为宿主原样字形——图标跟宿主走，本仓不维护自造路径，16px 下的可辨识度也不自己调。
- **展开/收起不再换字形**：展开态由行首悬停时的箭头（展开时旋转 90°）与会话列表本身表达，字形不再是状态载体。
- **顶部「项目」分区标题保留 `folder-open-outline`**：那是分区的图标，不是单个项目的入口；不动它，也避免同屏出现两个语义不明的网格。
- **删掉 `folder-close` / `folder-open` 字形**：换掉后没有调用点（未使用的代码直接删）。`folder-open-outline` 仍被分区标题引用，保留。
- **类名保留 `-folder` 后缀**：槽位的位置、尺寸、悬停规则都与宿主工作区行的目录图标同源，改的是字形不是槽位；改名要牵动 CSS 与测试的多处匹配，没有行为收益，在注释里写明以免下一个人以为漏改。

## 边界

- **「+」与添加项目按钮同形**：这是宿主字形自带的，接受它作为入口标识；项目行本身不做「新建」动作，新建在分区标题右侧。
- **运行中槽位不渲染行首图标**：本组有活动时槽位换成宿主 `StateDot`，与之前「目录图标不渲染」是同一条既有行为。
- **同屏其他网格类图标**（宿主侧栏的「更多」等入口）不做联动。
- **首版「新增 leader 会话行并给它九宫格」已整体回滚**：要改的就是项目行首本身，项目行保持文件夹的做法被用户否掉。
- **CSS 模板字符串里的反引号会在 import 期炸掉整个客户端半边**（模板截断、页面白屏），而 `node --check`、单测与覆盖率门禁全绿——那层只做语法检查，不跑模块求值。改 `src/client/` 里的 CSS 后先跑 `plugin.e2e.js`：它比业务场景快一个数量级，判据正是「插件能不能挂载」。

## 验证

`tests/project-panel.test.js` 与 `tests/e2e/project-workspace.e2e.js`（行首槽位恰好 4 条 `<path>`，能区分于目录字形）。双向：把渲染改回 `productIcon(expanded ? 'folder-open' : 'folder-close')` → 字形断言红；还原后全绿。
