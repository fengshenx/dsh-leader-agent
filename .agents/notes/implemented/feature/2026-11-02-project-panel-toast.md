# Agent Note: 项目区块的提示改为一次性 toast

Status: implemented

## Problem

左栏项目区块原有一套常驻提示：一次性的失败与删除成功回执都挂在区块尾部，直到下一次操作才清空——项目行当场消失后那句话还挂在侧栏里，用户觉得诡异；常驻位置还把「一次性的消息」说成「持续的状态」，与真正的持续状态（项目通道未就绪）混在一起。

## Decision

- **常驻提示行整个去掉**：区块尾部不再渲染任何提示。
- **一次性消息改走 toast**：自绘提示条挂在宿主 `shell.overlay` 槽位（跨栏浮层，窄侧栏收起项目浮层时提示仍可见），形态照宿主自带 Toast：顶部居中、暗色表面、不拦截点击、几秒后淡出。
- **同一时刻只留一条**：新消息替换旧消息并重启计时，订阅者按 id 撤销——旧提示的淡出计时器晚到时不会撤掉刚弹出的那条。
- **删除成功给一句回执**（「已删除项目「X」。」），几秒后消失。常驻才算噪音，一次性回执不是；工作区真摘除失败时在回执后带上原因，`notFound` 走幂等成功、回执不提工作区。
- **「项目通道未就绪」留在区块内**，不改成 toast：它是持续状态，弹一下消失只会让用户以为问题已经过去。这行常显在列表上方、不随列表折叠消失，就绪后自动换成项目列表；通道坏着时说「还没有项目」是误导，所以状态行与列表内容互斥。
- **自绘而不复用宿主组件**：宿主没有一行式的 toast API（`workspace.toast` 是 keyed 槽位，key 只认工作区自己的通知），`ui-primitives` 的 `Toast` 在宿主内部包里，本仓不 import 宿主内部包。
- **重命名校验失败保留编辑态**：提交判定抽成 `planProjectRename`——校验失败返回 `keep`，输入框与原因留在行内；名字没改返回 `close`；合法才 `commit`。接口失败仍走提示条，那不是输入能改好的问题。

## Alternatives considered

- **保留区块尾部的常驻提示**：一次性消息会被读成持续状态，项目行消失后提示还挂着；整行去掉。
- **复用宿主 `workspace.toast`**：keyed 槽位只认工作区自己的通知，没有通用一行式 API；自绘挂在 `shell.overlay`。
- **把「项目通道未就绪」也弹成 toast**：它是持续状态，弹一下消失会让人以为问题过去了；留在区块内。
- **让提示条堆叠**：面板操作受 `busy` 串行，连续两条只在少数场景出现，留最新一条够用。

## Consequences

- 取代了[项目删除合并为一个入口](../simplification/2026-10-30-project-delete-merged.md)里「删除成功提示分三支」的设计：三支合并为「一句回执 + 工作区摘除失败时带原因」。
- 提示条不堆叠，连续两条消息只看到最新一条；项目面板的操作受 `busy` 串行，并发两条只在挂载/聚焦时读取失败这类场景出现，丢一条可以接受。
- 提示条不带动作按钮（宿主 Toast 有 `actions` 座位）：本插件没有「撤销」类操作需要它。
- **提示条依赖宿主 `shell.overlay` 槽位**：`ctx.slots.inject` 在槽位从未声明时回调永不执行、不抛错，失败消息会静默丢弃。rc.2 的 web-app 声明了该槽位，宿主改名或移除时的故障现象是「提示全没了」。
- **未覆盖**：「项目通道未就绪」状态行的真机画面（需要宿主不提供 remote 服务的组合）；折叠态与行内错误只有单测覆盖。

收益：项目区块不再挂过期回执，一次性结果以跨栏 toast 出现，持续状态留在原位。
