# 项目行行距与拖拽排序

## 背景

项目行是高 34px 的整行底色、行间没有间距，相邻两行同时亮底色时粘成一整块（宿主工作区树在同一位置留了行距）；列表顺序又只能由建项时间决定，用户照着宿主工作区的拖拽预期去拖项目行，什么都不会发生。

## 决策

### 数组顺序即显示顺序，不另存序号

- `projects.json` 的 `projects` 数组顺序就是左栏显示顺序：`list()` 不再按 `createdAt` 排序，新项目 push 到末尾；`store.move(id, beforeId)` 在写串行链里把记录 splice 到锚点之前（DOM insertBefore 语义，空串表示末尾），落点与当前位置相同则不写盘。「末尾」用空串而非 `undefined`，因为远程入参在客户端有严格 codec。
- 不加 `order` 数字字段：数组本身已是有序容器，再存一份序号要处理老记录缺序、重排重编号、两种顺序混排，换不到任何东西；老数据本来就按建项时间 push，天然兼容。
- `move` 的锚点在并发删除后可能已不存在，这时落到末尾而不报错——目标没了用户无从修复，报错只是把一次正常操作变成红色提示。

### 落点判定与宿主工作区同一套半区规则

- 拖到目标行上半插到它之前、下半插到它之后（最后一行下半就是末尾）；判定收在纯函数 `projectDropAnchor` 与 `projectDropPlan` 里，**顺序不会变时返回 null**——拖回原处是常见动作，客户端不该为它发远程调用。
- 插入线画在项目块（行 + 展开的会话列表）上而不是项目行上：插入点按项目数组排，挂到行上时展开态的线会差出一整个会话列表的高。拖到源行本身不画线（拖起来后指针会从行上划过，线亮着而松手什么都不发生），落点在别的行上时线照画，只省掉远程调用。

### 客户端乐观重排，连续拖动串行收尾

- 落地先按锚点本地重排再发 `projects/reorder`：远程往返几十毫秒，行停在原处再跳过去会被看成「没拖动」。成功或失败之后都重拉一次 `projects/list`——成功时取宿主算出的顺序与派生字段，失败时用同一份真源撤销乐观重排。
- 连续拖动走串行写队列：两笔并发写出时服务端收到的先后不一定等于用户操作先后，两次刷新也可能倒序到达；队列让每笔等前一笔的请求与收尾都完成，且只有最后一笔做收尾刷新。面板没有周期刷新（只有窗口 focus），这个收敛只能由客户端自己保证。
- 写操作在途时不可拖：`draggable` 在 `renaming` 与 `busy` 时关掉——重命名时拖拽会抢走输入框的文本选择，删除/改名请求在途时拖动会与之交错。
- 行距照宿主工作区树：项目列表与会话列表都用相邻兄弟外边距拉开行距，不用容器 `gap`（项目列表是普通块布局，`gap` 不生效）；被拖起的行降低不透明度。

## 边界

- **没有键盘排序**：没有上移/下移入口或快捷键，行也不是可聚焦控件；要做是独立的键盘导航工作。
- **没有独立的「拖到末尾」投放区**：最后一行的下半区就是末尾，再加一块空白投放区只会和滚动区抢手势。
- **只排项目行，不排项目下的会话行**：会话顺序属于宿主的会话索引/工作区，本仓不持有它的真源。
- **拖拽中不禁用行点击**：浏览器在拖拽结束后不派发 `click`，实测拖完不会顺带打开会话，不需要额外的阈值判断。
- **插入线只在行的上下半区更新**：`dragover` 只在行的矩形上触发，指针进到展开后的会话列表区域时不改落点。
- **`openProject` 的挂工作区不走 `busy`**：它改的是工作区归属而不是顺序，且与 `move` 在同一条串行链上，不会互相覆盖；把 `busy` 摊到所有远程调用会让「点开项目」把整张列表锁一秒。要收口应给它独立的 `attaching` 标记，而不是复用 `busy`。
- **末笔刷新的「闪回一次」不修**：末笔刷新在途时再拖一笔，界面会闪回一次旧顺序，随后被新一笔的串行刷新追上（最终收敛，落盘始终正确）；修法要把「刷新」拆成两份实现，只为一个几十毫秒的窗口。
- **未覆盖**：触屏与移动端的拖拽（HTML5 DnD 在触摸设备上不生效）、窄导轨浮层里的拖拽，以及 `busy` 时不可拖（只做了静态核对）。

## 验证

`tests/projects-store.test.js` 与 `tests/project-panel.test.js`。双向：去掉 `projectDropAnchor` 的顺序判据 → 「顺序不会变的落点返回 null」红；把 `createWriteQueue` 的 `push` 改成立即执行 → 「连续拖拽串行写入」红。还原后全绿。
