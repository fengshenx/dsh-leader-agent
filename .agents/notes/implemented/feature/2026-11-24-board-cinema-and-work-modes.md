# Agent Note: 看板新增炫酷（线路图）与工作两种模式

Status: implemented

## Problem

看板原本只有一种纯列表：日常扫任务够用，但录屏、发社交媒体时看不出「leader 把活分给了谁、数据在往哪流」。用户要的「炫酷」不是换卡面材质，而是一张工作流图：卡片挂在主干上，执行者是支线，只有真实的数据流才上强调色。

约束：工作模式必须还是现在这套列表；线路图在浅色宿主下也要有能看的版本——第一版强行在所有主题下用深色面板，用户否掉后要求补一套浅色皮。

## Decision

- 两种模式：显式选择存 localStorage（跟浏览器走，不写项目数据）；没选过时用宿主判的默认值——升级前已有项目/卡片的老用户默认工作，新装默认炫酷。同一运行时用模块级订阅即时生效，其它窗口靠 `storage` 事件同步。
- 线路图是「列表 + 垫在下面的 SVG」，卡片与入口的 DOM 语义不变；渲染后实测行位置，几何规划是纯函数，绘制单独一层。
- **两套皮跟随宿主主题**（`ctx.theme` 的快照 + `theme/change` 事件）：浅色宿主走电蓝正交（支线直角、节点小方块，卡面与文字沿用宿主 alias 令牌，只重画板底与轨道）；深色宿主走黑金曲线（把 alias 重绑到主题无关的 `--dsw-static-*` 标尺）。颜色只给「执行中」的横段与支线；需注意只染节点与执行者圆环，结构线保持中性，避免主干被相邻卡片的档位染成一段蓝一段红。
- **流动按执行者自己的状态判定**，不跟卡片级信号走：同一张卡上两个 worker 一跑一停时，只有 running 的支线跑光点，idle 的支线保持中性；卡片这一级的 tick/节点仍按聚合信号上色。重画签名因此带上每个槽位的状态——只带卡片级信号时，一跑一停不会触发重画。需注意的线不流动，只用缓慢呼吸提示；它和光流是两种语义，不能都叫「在动」。
- **默认值落地前不画线路图**：宿主判定的默认模式是异步取回的，首帧读到「没有偏好」时不能把内置的炫酷当成用户选择，否则老用户会先闪一下 cinema 再切回工作。模式快照带 `resolved`，未就绪时按无 rail 的列表渲染。默认值 RPC 本身失败时也要结算一个模式：缓存里已有数据算出的默认就沿用，否则回退内置默认并广播，不能让看板永远停在 `pending`。
- **减少动态效果要订阅变化**：SMIL 光点不受 CSS 媒体查询管，只在绘制时读一次会让看板打开后切 reduce 的光点继续跑。订阅 media query 变化并重画，偏好切换时把已经挂上的光点摘掉。
- 看板不套外框、也不加分割线：去掉面板边框/圆角/投影/底色，看板直接落在宿主 pane 上，避免「面板 → 边框 → 卡片」三层。面板底色 `#f9fafb` 和 Tab 药丸的 `#f1f3f5` 只差 8 级、看起来是一块，所以底色也一并去掉；上方用 Tab 药丸本身区分，不额外画线。
- **新老用户的默认模式**：老版本没留过安装标记，浏览器里分不出新老；宿主在升级后首次启动时按数据根写一次性 `board-default.json`（已有 `projects` / `cards` 即 legacy），客户端把它缓存到 `board.default`，显式 `board.mode` 永远优先。标记只写一次，之后删光数据也不翻默认；新浏览器也按宿主数据判，不会因为清缓存变回炫酷。标记只是缓存：写失败（目录只读、磁盘满）仍返回按数据算出的默认值，不把默认判定一起判死。
- 执行者移到卡面右侧竖槽并全部展示，不用 `+N` 折叠；竖槽比卡面高时行跟着长高、卡片居中，支线向上向下散开。竖槽宽度取 `clamp(44px, 17%, 60px)`，卡面到圆点的可见连线约 40px——再长会把卡片挤窄，再短就没有「线」的读感。
- 重画由「模式 + 主题 + 卡片 id + 信号」签名触发，轮询换数组不会让光点重头跑；尺寸变化由 `ResizeObserver` 兜住。
- 设置入口用宿主的 `settings.section` 槽位；槽位不存在时静默缺席，看板按默认模式走。

## Alternatives considered

- **深色玻璃 / 任务控制台换皮**：用户明确否掉，要的是节点与连线，不是另一种卡面材质。
- **星型 / 流式布局**：都做进模拟稿比较过，420px 面板里星型挤成一团、流式看不出归属，用户选线路图。
- **第一版浅色皮（格纹背景 + 卡片渐变 + 投影 + 整条金线加光晕）**：实拍就是「脏」，用户否掉；问题不在浅色本身，在材质语言。
- **浅色也沿用黑金**：白底上金线发褐，且与宿主浅色界面冲突；金色只适合深色底。
- **给主题再加一个手动开关**：宿主已经有浅色/深色/跟随系统，再叠一层会打架；跟随主题是唯一不产生矛盾的选择。
- **用 localStorage 里旧 key 判新老**：旧版本只写过会话标签与引导卡关闭标记，没开过标签、没关过引导卡的老用户会被误判成新用户；只在客户端判不可靠。
- **执行者留卡内、只画断头线**：支线会被卡面盖住，是假连线，违背「线表示归属」。
- **CSS `offset-path` 替代 SMIL**：同一条路径要复用给 trail 与 comet，收益只是少一个元素。

## Consequences

- 线路图模式每个卡片行多一层包裹，执行者从卡内移到右侧竖槽，键盘顺序不变（卡面 → 执行者）；执行者多时行会变高。
- 两套皮都只作用于看板列表，详情浮层 portal 到 body，不受影响；浅色皮不覆盖宿主 alias，深色皮才重绑。
- 显式模式按浏览器保存，换浏览器、换机器不跟随；默认值按宿主数据根判一次，换浏览器会回到同一档默认。主题跟随宿主，旧宿主没有 theme 服务时退回系统偏好。
- 线路图与模式切换的 UI 判据进 e2e：`board-cinema` 钉住默认炫酷、rail 行/槽位由卡片驱动、切工作后 rail 消失，并覆盖 reload 的两条恢复路径（宿主恢复看板 / 收起右栏后重新导航）；`board-card-kind-navigation` 显式钉工作模式，因为它数的是卡内槽位。
- 2026-11-25 后续调整：默认改为工作模式，宿主一次性判定与 `board.default` 缓存移除；见 [2026-11-25-board-default-work.md](2026-11-25-board-default-work.md)。
- 使用手册补了模式说明；`docs/usage.md` 原本就贴线，按门禁把天花板从 7402 抬到 7600（attention 的呼吸口径又加了一句），没有删原有内容。
- 收益：同一块看板在演示时能一眼看出派工拓扑，浅色宿主下也不再是一块突兀的黑面板。

## Testing

- 单测钉住模式规范化、读写失败与订阅广播，以及「显式选择 > 宿主默认缓存 > 内置炫酷」的优先级与缓存写入条件；模式快照把「偏好未就绪」与「已就绪的炫酷」分开；默认值 RPC 失败时沿用已有缓存或回退内置默认。
- 宿主一次性标记钉住：无数据 → fresh、有项目/有卡片 → legacy、标记只写一次、标记损坏时按数据重算、标记写失败仍按数据返回默认；远程方法钉住取值与漏传装配报错。
- 线路几何钉住信号到线语义、tick 路径、正交拐角、退化直线、坐标取整，以及「支线按槽位状态分档、槽位缺状态时退回卡片级」；样式门禁钉住「需注意的线只呼吸不跑光流」与设置页预览圆点取主题强调色。
- 减少动态效果的订阅用假 `matchMedia` 钉住：变化回调、退订、老 WebKit 的 `addListener` 与接口缺失时的空操作。
- 样式门禁的白名单逐条对 `dsh-client-ui-theme@0.2.1-rc.2` 的产物核过，浅色/深色两套的 token 都在内。
