# 项目与 dsh 工作区解耦：不建、不挂、删项目不动工作区

## 背景

两个报障同源：在项目目录的工作区里新建会话，打开的是项目 leader（宿主把工作区里的「第一个空白会话」当可复用的新建草稿，而旧版本把 leader 挂进了项目目录的工作区）；删项目连工作区一起删，删工作区点项目行又自动重建。项目与工作区被绑成一条命，而归属本来只是为了分组，不是可打开性。工作区行在渲染层始终可见，本仓只排除项目会话行。

## 决策

- **项目不碰工作区**：`create` 只建 leader 会话与记录（不传 `workspaceId`）、`replaceLeader` 只确认目录可用、`remove` 只删记录；项目记录不再有 `workspaceId`，挂载、归属登记、重建与丢弃工作区的相关函数全部删除。
- **渲染层接管「未分组」组头**：组内已渲染的会话行全被隐藏、且没有可见的「展开其余 N 个会话」时给组头加标记。判据只看 DOM 现状，不复刻宿主的可见性规则——复刻规则必然漂移，这正是推翻早期路线的理由。
- **历史挂载在启动时摘掉，只摘项目目录那个工作区**：目标集合是现任 leader、退役 leader 与登记的 worker；只对「工作区目录 realpath 归一后等于某个项目目录」的工作区调 `detachSession`。旧版本的自动挂载本来就落在项目目录对应的工作区，收窄不会漏摘；用户手动开的会话不动。
- **要用 `ctx.inject(['workspaceRegistry'], …)` 等宿主服务就绪**：插件 `apply` 期间 `ctx.get` 是 `undefined`，迁移会静默变成空操作（第一版就是这么错的，日志干干净净）。
- **不要遍历工作区的 `sessionIds` getter**：它按会话 cwd 索引过滤，刚重启时历史会话可能还没索引到——要摘的恰好就是这类。对目标集合里的会话直接调 `detachSession`，包不包含交给宿主在写入链里判。
- **删项目语义简化**：回执只区分 `removed` 与「没找到」；`workspaceRemoved` / `skipped` 这类回执随归属一起删掉，确认弹窗与结果提示改成「文件夹、会话记录与 dsh 工作区都会保留」。

## 边界

- **迁移每次启动都跑一遍**：项目数 × 工作区数的 `detachSession` 调用（基本都是空操作），量级小，避免再加「迁移版本号」这类状态。
- **没有工作区服务的组合（acp / headless / sdk）里迁移不跑**：等不到服务，也没东西可摘；worker 身份收编不依赖工作区，不受影响。
- **用户在项目目录里自建的工作区照常显示**：会话行仍被排除、折叠计数按排除后修正；删项目不动它。
- **迁移按目录配对，不按会话并集**：摘除集合是「该项目自己的 leader / 退役 leader + 全局 worker」，否则 B 项目的 leader 被拖进 A 项目目录的工作区时会被 A 的迁移连带摘掉；用户手动分组到其它工作区的那一份归用户所有。
- **目录解析失败时归一器回落原字符串**：项目目录被删或改名后，那批老挂载会漏摘；影响仅限「目录已经不存在的项目」，彻底修要在项目记录里存 canonical 目录。
- **「未分组」组头判据只看 DOM**：宿主若改成空组头直接不渲染，这条补丁自然失效，不会反过来藏掉有内容的组。
- **存量记录里的 `workspaceId` 不迁移、不读取**。

## 验证

`tests/e2e/project-workspace.e2e.js` 跑完整两段式实例（旧数据 seed → 启动摘挂载 → 点项目行打开 leader → 未分组组头隐藏 → 新建会话不再是 leader）。双向读数：撤掉 `ctx.inject` 里的迁移调用，e2e 读到 `workspace.json` 里 leader 仍在而超时变红；把按目录配对改回全局目录集合，「不摘别的项目拖进来的 leader」用例变红。
