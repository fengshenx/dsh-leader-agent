# 项目作用域与角色槽位

> **部分已被 [项目与 dsh 工作区解耦](2026-11-03-project-workspace-decoupled.md) 取代**：项目不再注册工作区、不把 leader / worker 挂进去，本文原「协调者会话必须归属工作区」「插件工作区的归属记进项目记录」两节已删；项目作用域、角色槽位与左栏项目区块仍然有效。

## 背景

协议层、派工唤醒、卡片与右栏看板已交付，dsh 还缺**项目作用域**与**角色槽位**。dsh 的 `workspace` 家族是工作区语义（目录 + 会话归组），不是项目语义（编排语境），二者不合并；它又只在 web-app bundle 挂载，第三方不能写进 `inject`。项目是显式注册、有名字、可注销、与协调者会话硬绑定的实体，目录只是它的一个属性——首版「项目 = 有会话的目录集合」的实现已整体废弃。

## 决策

- **项目 = 显式注册的持久实体**：`id` / `name` / `directory` / `coordinatorSessionId?` 落盘在独立注册表，自建存储域（原子写 + 读-改-写串行链 + 损坏时备份并写回空库），不用宿主 storage domain。
- **项目 ↔ 协调者会话硬绑定**：会话头是封闭字段、没有自由元数据槽，指针只能存在项目记录里，这是绑定关系的唯一真源；切项目 = 打开该项目的协调者会话（另一个 cwd 的会话）。
- **建项目 = 建实体 + 建协调者会话 + 绑定，失败整体回滚**：先建会话再落盘，落盘失败尽力撤销会话；会话创建优先 `sessionController`，降级 `agents`（全 profile 有），两条都拿不到时如实报错、不静默降级。
- **worker 目录由项目决定，协调者不能指定**：派工时按父会话反查项目目录，授权真源是项目目录而非 cwd 约定。
- **项目 ↔ 会话归属自建内存索引**：提示词组装与派工是同步路径、存储层是异步的，所以落盘之外另建内存镜像并在启动时重建；索引只服务读侧，落后一版只影响当轮派工目录。
- **槽位读项目目录的 `SLOTS.md`**，目录优先级「项目目录 → 会话头 cwd → 外部回调」；注入是**运行时上下文 provider** 且声明 `required`——每轮重新求值，变更在下一轮 turn 生效；**槽位不授予工具权限**，只贡献一段提示词文本。
- **client → host 走 Typert 的 SRC 远程通道**（命名空间 `projects`，复用官方 `/api`）：自建 Web 路由对仓外插件不成立（`rpc.handle` 的作用域拿不到 webServer，`/api` 已有官方拦截器）；宿主在 strict 描述符缺失时按服务原型标记与实例绑定回退还原，本仓手写同形状的标记、绑定与客户端贡献即可，不装 dsh 内部包。
- **远程方法名要避开官方命名空间服务的保留字**：撞上即拒收**整个命名空间**，删除入口因此现名 `deleteProject`。
- **左栏项目区块靠 DOM 注入取位**：slot 体系没有与工作区并列的槽；宿主改版会让位置漂移，找不到锚点时退回原槽渲染。
- **client 侧会话导航惰性获取 + 降级**：`uiWorkspace` 由 web-app bundle 提供，不写进 `inject`，缺失时提示用户在目标目录新建会话。
- **项目树自建，与官方工作区树并行**：重复出现的会话行在渲染层按 `data-row-key` 排除，官方数据层不动；工作区行始终可见，不借用官方归档接口做排除（归档是用户可见的持久状态）。
- **排除器的观察回调按帧去抖**：观察整棵文档，流式渲染会连续触发；取消时一并取消待执行扫描。
- **项目下只列 worker 会话**：目录相等**且**登记表说它是本 bundle 派出的 worker（此前看 `origin: 'subagent'`），协调者会话的入口在项目行上。
- **会话归属判定放在宿主侧**：浏览器没有文件系统，宿主按 realpath 归一后比对 cwd，经远程方法 `sessionsByProject` 下发；子目录里的会话不算，两个项目指向同一目录时先注册的项目拿归属，协调者会话不在子会话列表里。
- **项目树两处折叠，点项目行本身是「打开该项目的协调者会话」**：标题折叠整个列表、行首槽位折叠子会话；项目名后不跟路径（放进悬停提示）；行形态照抄官方工作区行——槽位平时目录图标、悬停换箭头、展开旋转，操作按钮贴行右端。
- **图标自己内联，不引用宿主 sprite**：web 端运行时没有 sprite 节点（宿主自己的图标也是内联 path），`<use>` 一律落成 0×0 且不报错；代价是与宿主图标数据耦合。
- **项目不碰工作区**：只建 leader 会话与记录，不注册、不挂载、删项目不动工作区；历史挂载在启动时按目录摘掉。
- **「更多」菜单复刻官方材质并挂 portal**（仓外插件用不了官方 Menu 组件），支持 outside click 与 Escape；会话行是纯文字行，行首只留状态位。
- **协调者会话靠第三方会话视图目标顶进官方 active 形态**：注册一个只提供活动、不产出内容的视图目标，打开时激活——输入框停靠底部、不跑首轮、不产生模型调用、转录为空；目标不注册成可见 tab（`conversation.view` 不能按会话过滤，会出现在所有会话头部）。激活动作挂在 `conversation.input.dock` 槽位并在 layout effect 里执行（不会先闪一帧欢迎页），激活是 per-binding 的。
- **协调者会话名单独立拉取**：不能挂在会卸载的项目面板上，通道就绪与窗口重获焦点时补拉。

## 边界

- **编号仍全局递增、卡片不按项目分区**：按项目编号要迁移存量卡片（[卡片存储与编号作用域](2026-10-23-card-storage-and-numbering-scope.md)），`@#n` 按全局编号解析。**项目实体只有 name 与 leader 指针可变**：目录创建时定死，目录变了就等于换了一个项目。
- **排除只发生在渲染层**：官方分组行的会话计数与实际可见行数对不上，被排除的行仍在 DOM 里（搜索等数据层功能仍能命中）；用户把项目目录加进 workspace 时，官方那棵分支下的会话行仍被排除——判据是项目目录，与 workspace 归属无关。
- **两个项目指向同一目录时子会话归属先注册者**；注销项目保留协调者会话，不做级联删除。
- **区块靠 DOM 注入取位、图标路径抄宿主 artwork、手写 Typert 形状与宿主版本耦合**：宿主改版要同步并重跑契约测试。
- **槽位变更对在途 turn 不生效**（提示词在 step 前组装），运行时上下文是增量快照（正文不变的那轮不重复注入）。
- **槽位只对绑定了卡片槽位的会话生效**：`renderRoleContext` 查不到槽位名就返回空串，未绑定时不注入任何角色正文，也不会退化成整个项目的角色设定。
- **协调者形态依赖宿主 `uiConversation` 服务**：缺失时退回官方欢迎页、不阻断打开；激活只覆盖协调者会话，官方普通空白会话仍是 hero；不改动宿主投影——只是让外壳命中另一条判定分支，不伪造会话历史。图标渲染层没有单测（依赖宿主注入的 `react`），靠浏览器实测取证。
