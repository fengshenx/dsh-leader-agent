# 删除项目后不再留常驻提示

**状态**：current（2026-11-02）
**范围**：`src/client/project-panel-logic.js`、`src/client/project-panel.js`、`README.md`

## 背景

删除项目成功后，左栏「项目」区块尾部会一直挂着「已删除项目「X」。文件夹与会话记录保留。」，直到下一次操作把它清空。用户删掉一个项目后看到这句留在侧栏里，反馈「太诡异」。

这句没有新信息：二次确认弹窗在删除前已经讲清文件夹与会话记录都会保留；删除后项目行当场消失，行消失本身就是回执。

## 决策

- **删除成功一律不提示**，包括工作区被摘除（`workspaceRemoved`）、没有可摘的工作区（`skipped`）、项目已不存在（`notFound`）三种成功形态。与建项目同一口径：行本身是回执，只有失败才在区块尾部给提示。
- **只有工作区真摘除失败仍报**：「已删除项目「X」。工作区未移除：<原因>」。项目记录已经删掉，用户再也看不到这个工作区属于谁，只能去官方面板手动删——这条不能静默。
- **`notFound` 的 `reason` 不能当工作区告警**：它是「项目不存在」，走幂等成功支，提前返回空字符串。
- **确认弹窗文案不变**：它讲的是删除前会发生什么，与删除后的提示是两件事。

## 边界

- 覆盖了[项目删除合并为一个入口](2026-10-30-project-delete-merged.md)里「删除成功提示分三支」的设计：那三支现在合并为「静默 + 真失败」两支。

## 取证

- **单测**：`npm run check` 515 例全绿。
- **双向验证（单测）**：把 `describeDeletionNotice` 改回旧三支 → 6 例变红（4 条「真实 service → remote → 文案」链路、1 条 `notFound`、1 条纯函数），还原后全绿。
- **真机**：`.dev/home` 隔离实例（`DEV_PORT=3292`），seed 两条没有 `workspaceId` 的项目（删除走 `skipped` 支），点「更多」→「删除」→「删除」：
  - 本支：项目行消失，侧栏项目区块没有任何提示文本；注册表只剩未删的那条。
  - 撤销修复（旧逻辑）：同样操作后侧栏出现「已删除项目「probe-b」。文件夹与会话记录保留。」——与用户看到的形态一致。
  - 「更多」按钮是 hover-only，无头浏览器里点不到；取证期间临时把 `.dsh-leader-kit-project-actions` 改为常显，取证后已还原（该文件不在本次 diff 内）。
- **未覆盖**：`workspaceRemoved === true` 那一支的真机画面（截图不入库）；该支与 `skipped` 支在客户端走同一个「静默」出口，由单测覆盖。
