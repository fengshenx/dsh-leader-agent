# Agent Note 的格式交给机械门禁，不靠记性

## 背景

宿主仓库早就有这件事：`scripts/verify-agent-note-format.ts` 检查头部块、首节 `## Problem`、按生命周期
必备的章节、`## Alternatives considered`，挂在 `scripts/run-gates.ts` 的 `doc-sync` 门禁上（`quick: true`）。
本仓一直没有对等的检查——`npm run check` 只做 `node --check` 与 `node:test`，`.agents/notes/` 的
结构全靠人。

代价当场付过一次：新笔记按「一个问题一节」写，`##` 全是主题名，没有 `## 背景` / `## 决策`，人和
review bot 都没发现，是用户读出来才改的。规则写在 `AGENTS.md` 里也拦不住——散文规则要在写的时候
被想起才生效，机械门禁在 `npm run check` 里必然被执行。

## 决策

新增两个文件，判定与 IO 分开（本仓「可判定逻辑抽纯函数再测」的惯例）：

- `scripts/agent-note-format.mjs`：`checkNote(name, text)` 返回违规项数组，纯函数。
- `scripts/verify-agent-note-format.mjs`：读 `.agents/notes/*.md`、逐篇判定、有违规则列出并退 1；
  格式与宿主的入口同一形态（成功打一行计数）。

接进 `package.json` 的 `check`，排在语法检查与单测之前。

四条规则，都是「漂了就一定读得出问题」的最小集：

1. 文件名 `YYYY-MM-DD-<english-slug>.md`，日期要真实存在（`2026-13-01` 不算过）；
2. 唯一的 H1，且是文件第一行；
3. 第一节必须是 `## 背景`，且必须有 `## 决策`；
4. 同名 `##` 不能出现两次。

围栏里的 `#` 不计入结构（笔记里贴 markdown 示例是常态）。

**不照搬宿主的骨架**（`# Agent Note: <title>` + `Status:` + `## Problem` / `## Decision` /
`## Alternatives considered` / `## Consequences`）：本仓原有的 31 篇已经按 `背景 / 决策 / 边界 / 验证` 写，
换成宿主的头部块与英文节名要重写每一篇，收益只是「和上游长得一样」。门禁管的是自洽，不是同形。

同一 PR 里把 4 篇不合规的历史笔记按现行骨架重排：`2026-10-29-worker-preset-mount.md`（现象/根因 →
背景/根因，修法 → 决策，遗留 → 边界）、`2026-10-30-quiet-workspace-activation.md`（问题/做法 →
背景/决策，与前次决策的关系降为 `###`）、`2026-10-30-retired-coordinator-sessions.md`（问题/测试 →
背景/验证）、`2026-11-02-rename-to-leader-kit.md`（为什么改名/改动/没改的 → 背景/决策/边界，数据目录降为 `###`）。
只动标题层级与段落归属，正文一字未改。

## 边界

- **只查结构，不查内容**：篇幅、是不是流水账、验证有没有读数、决策有没有写理由，门禁一概不管。
  那要读得懂中文并且知道这个改动做没做，机械判不了。
- **不强制 `## 边界` 与 `## 验证`**：历史笔记里有几篇只有 `背景 / 决策 / 证据` 或 `背景 / 决策 / 取舍`，
  硬性要求会逼人补写本不存在的验证内容——那是给门禁凑数，比缺一节更坏。新笔记按 `AGENTS.md` 的
  约定写全，靠 review 兜。
- **不查跨笔记链接**：宿主的 `verify-md-links` 在本仓没有对等物，改名或删笔记留下的死链要人手扫。
- **只查日期在日历上合法**，不查与 git 首提时间是否一致——那得问 git，不该由 `npm run check` 承担。
- **没有祖父条款**：宿主给 `FORMAT_ADOPTED = 2026-07-05` 之前的笔记开了注释豁免，本仓一次性把 4 篇
  重排完，不留豁免通道，免得「豁免」变成新笔记的默认出路。

## 验证

- `npm run check`：547 例全绿（新增 `tests/agent-note-format.test.js` 9 例），门禁打印
  `verify-agent-note-format: 34 篇笔记格式合规`（合入 main 后再加两篇，合并提交里复跑）。
- 用例覆盖：合规模板不报、文件名四种写错、日期不存在（含闰日 `2028-02-29` 反例）、H1 非首行 /
  缺 H1 / 两个 H1、首节不是背景、缺决策节、同名节重复、围栏内 `##` 不算结构、仓库全部笔记合规。
- 双向验证 5 组，逐项撤销 → 对应用例变红 → 还原全绿：
  端到端（把 `2026-10-30-retired-coordinator-sessions.md` 的 `## 背景` 改回 `## 问题`，门禁退 1 并报
  「第一节必须是 `## 背景`」，还原后退 0）；撤「首节是背景」判定（1 例红）、撤「日期真实存在」
  （1 例红）、撤「H1 唯一」（1 例红）、撤「节名不重复」（1 例红）。
