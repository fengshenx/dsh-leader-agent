# README 只留用法，架构下沉到 docs/architecture.md

## 背景

README 长到 213 行、43KB，同时承担两种职责：入门的「这是什么、怎么装、怎么用」，与开发者的「模块怎么分、数据怎么流、为什么这样取舍」。后果是两头都不好用：

- 新读者要穿过一张 33 行的模块表和十几段机制论证才看到安装命令；
- 使用说明与实现细节混在同一批编号列表里，改一处行为要在 README 里找几个不相关的段落；
- 35 条「已知限制」直接压在 README 末尾，既是最该给用户看的部分，也是最难读完的部分。

仓库已有 `AGENTS.md`（常驻规则）、`docs/capability-gaps.md`（宿主边界）、`docs/e2e-testing.md`（取证规范）、`.agents/notes/`（决策记忆），唯独缺一份讲整体架构的长期文档——那部分内容此前一直寄居在 README 里。

## 决策

**README 只写四件事**：功能、安装、基本使用、当前限制；另加开发命令、致谢与文档导航。现在 113 行。

**使用细节下沉到 `docs/usage.md`**（63 行）：原 README「使用」一节的完整交互（派工与续聊、卡片、看板与信号灯、项目管理与归档、`SLOTS.md`、`COORDINATOR.md`）逐段迁入，README 的「基本使用」只保留七步最短路径。这些是操作手册内容，不是架构，因此不塞进架构文档。

**架构内容下沉到 `docs/architecture.md`**（335 行），承接：

- 分层（宿主侧 / 客户端 / shared / 协议层，零运行时依赖的边界）；
- 运行时模型：三种会话身份、worker 常驻根会话、派工与唤醒、通知投递的两条硬边界；
- 项目与会话归属、卡片与看板、客户端注入面、持久化布局、项目级提示词；
- 原 README 的模块表与编排动作表，保留逐行说明；
- 开发一节：多 worktree 并发、开发实例、worktree 清理、测试与构建；
- 宿主契约与架构约束、协作与文档机制、阶段编号；
- 完整的限制清单（见下「限制清单去重」）。

**README 新增「前提：先跑通多 worktree 并发」一节**，明确这套架构的玩法建立在任务隔离之上：每个任务一个 worktree、一个独立 dsh 实例、一份独立数据根。没有这一层，派工落在同一 checkout 上互相踩，编排价值不成立。同节列出建议蒸馏的四项 DeepSeek Harness 团队实践（worktree 并发、Agent Note、AGENTS.md 渐进式披露、文档防腐化），并指出本仓各自的落点，方便把这套玩法搬进别的项目。

**README 加致谢**：Cursor 的 Project 实现与 PStack 的编排机制（项目作为一等实体、按项目聚合会话与交付物、协调者派工 / 执行者回报 / 交付看板这条主线）；DeepSeek Harness 团队的宿主契约与工程实践。

**引用同步**：`AGENTS.md` 的「按任务查阅」新增架构文档入口、目录说明的 `docs/` 职责补上「架构」；`docs/capability-gaps.md` 第 13 条里指向 README「已知限制」的引用改指 `architecture.md#已知限制与取舍`。

### 限制清单去重

原 README 的两条编号类限制（「卡片编号仍是全局的」与「卡片编号跨项目不复用」）说的是同一件事，合并为一条，清单从 35 条变 34 条。README 因此不写条数，只写「完整的限制清单」——写死条数会在下次增删时立刻过期，属于文档防腐化要避免的那类数字。

## 边界

- **纯文档改动**：不改代码、不改运行时行为，不新增功能。
- **README 保留 `## 开发` 锚点**：`AGENTS.md` 的 `README.md#开发` 链接沿用，不需要改指向。开发细节留在 README 与架构文档两处：README 给命令，细节给架构文档。
- **架构文档记录现状与取舍，不是规格书**：它不承诺尚未实现的能力；新能力先落代码，再同步文档。
- **跨文件锚点靠人工核查**：本仓没有 markdown 链接门禁（见 `2026-11-02-agent-note-format-gate.md` 的边界），`docs/` 之间的 `#` 锚点不会被 `npm run check` 覆盖。
- **不改 `.agents/notes/` 的历史笔记**：它们描述的是当时的决策，不随文档拆分而重写。

## 验证

- `npm run check`：580 例全绿，Agent Note 格式门禁通过。
- 内容迁移核对：原 README 的 35 条已知限制全部有落点（34 条，两条编号类合并）；「使用」一节的完整交互逐段迁入 `docs/usage.md`；模块表与编排动作表原样迁入，仅路径引用从 README 相对位置改为 `docs/` 相对位置。
- 相对链接核查脚本（三份文档的每个非锚点链接逐个 `test -e`）：无缺失。
- 锚点核查：README 指向架构文档的三个锚点（`#协作与文档机制`、`#已知限制与取舍`、`#开发`）与架构文档指向 README 的 `#前提先跑通多-worktree-并发` 均对应实际标题。
- 规模读数：README 213 → 113 行；`docs/usage.md` 新增 63 行；`docs/architecture.md` 新增 335 行。
