# 文档按层归属，并给 standing docs 加体量门禁

2026-11-03。

## 背景

宿主仓库对文档有两道预算，本仓此前一道都没有：`@deepseek-ai/dsh-agent-instructions` 的注入预算只作用于 `AGENTS.md` / `CLAUDE.md`（每条链 65,536 字节，`docs/` 下的文件不进这条链）；`scripts/verify-doc-budgets.ts` + `doc-budgets.manifest.json` 则给 standing docs 设词数天花板（宿主 `docs/architecture.md` 是 2,410 词，当前 2,386）。本仓 `npm run check` 只有 Agent Note 格式与文档工具名两道门禁，体量不受约束。

`docs/architecture.md` 因此长到 60,309 字节 / 15,999 个单位 / 357 行 / 27 个小节，是宿主同位置文档的三倍。体量来源是两类与代码同频变化的内容：36 行的逐文件职责表（9,035 字节，最大单节）与整节已知限制（约 18,000 字节）。此外开发节与 README、`AGENTS.md` 三处重复讲同一批开关，末尾还有「P5 已完成」这类实现状态标注。代价是改任何一处实现都要同步改架构文档——而它是「先读再改」的地图，读者还要为这份体量付上下文。

## 决策

### 一个事实一个归属

分层表放 `AGENTS.md`（层 → 管什么 → 不写什么），并断言改代码时只改事实已经变化的那一层，架构文档只在组成、接缝或数据流变化时改。`docs/architecture.md` 只留有序地图：分层、运行时模型、数据流、持久化布局、宿主契约落点。

### 限制与开发各自成文

新建 `docs/limitations.md`（限制是什么、为什么这样取舍）与 `docs/development.md`（开发环境、实例、构建契约、测试机制），原样承接架构文档里对应的两节；README 只留使用者向概览与命令速查，细节链过去。逐文件职责表删除——文件头注释是权威来源，不在文档里再抄一份。阶段编号一并删除，`capability-gaps.md` 开头留一句说明它已不再维护。

### 计数口径：CJK 字符 + 空白分词

`wc -w` 对中文失效（整段算一个词），照搬会把 13,000 汉字的文档测成 2,536 词。改为 CJK 统一表意文字逐字算 1、其余按空白分词，代码块与表格一并计入。口径只求稳定与可解释，不追求与 token 数等价。

### 天花板按当前值加约 5% 余量，超限先搬层

清单在 `scripts/doc-budgets.json`，入口 `scripts/verify-doc-budgets.mjs` 接进 `npm run check`。判定红了按「搬到对的层 → 压缩 → 抬天花板」处理，抬天花板要在 PR 里写明理由（与宿主同一规则）。`.agents/notes/` 与 `.agents/skills/` 不设预算：前者是历史累积，后者按需加载。

## 边界

- 门禁只判体量，不判归属正确性：把细节搬到错误的文档里，它照样绿。避免重复靠的是分层表，不是机械判定。
- 同一事实写在两处时，只有其中一份先撞天花板才会被发现；两处都短就能长期共存。
- 章节搬迁会断锚点链接，本仓没有 Markdown 链接门禁：改结构时 grep 一遍 `architecture.md#`。历史 Agent Note 里的旧锚点保持原样——它们记录的是当时那次同步动作，不是当前权威。
- 预算单位是体量代理，不是 token：中文 1 字与英文 1 词的信息量并不等价，跨语言对比没有意义。
- 注入预算（65,536 字节/链）仍由宿主执行，本仓不重复实现；它只管 `AGENTS.md` 这类指令文件，`docs/` 的体量由本仓门禁管。

## 验证

- `docs/architecture.md`：60,309 字节 / 15,999 单位 → 18,289 字节 / 4,733 单位（-70%），与宿主同位置文档（18,884 字节）持平；天花板设 5,000。
- `docs/limitations.md` 5,272 / 5,600，`docs/development.md` 1,602 / 1,700，其余 8 份 standing docs 全部在各自天花板内。
- 新增 `tests/doc-budget.test.js` 6 条：CJK 与空白分词口径、代码块与表格计入、ok/over、missing 与非法天花板各自单独报出、输出行内容、真实清单声明的文件都存在。
- `npm run check`：809 tests / 800 pass / 9 skipped / 0 fail（新增 6 条）；Agent Note 门禁 51 篇、文档工具名门禁 11 篇、文档预算 10 篇全过。
- 双向验证 A（门禁入口）：给 `docs/architecture.md` 追加约 3,100 个单位 → 报 `OVER 7858 / 5000`、退出 1；还原后 10 篇全绿、退出 0。
- 双向验证 B（计数口径）：把 `countDocUnits` 的 `cjkCount` 恒置 0 → 两条口径用例变红（4 pass / 2 fail）；还原后 6 / 6 绿。
