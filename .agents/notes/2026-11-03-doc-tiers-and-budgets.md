# 文档按层归属，并给 standing docs 加体量门禁

2026-11-03。

## 背景

宿主仓库对文档有两道预算，本仓此前一道都没有：`@deepseek-ai/dsh-agent-instructions` 的注入预算只作用于 `AGENTS.md` / `CLAUDE.md`（每条链 65,536 字节，`docs/` 下的文件不进这条链）；`scripts/verify-doc-budgets.ts` + `doc-budgets.manifest.json` 则给 standing docs 设词数天花板（宿主 `docs/architecture.md` 是 2,410 词，当前 2,386）。本仓 `npm run check` 只有 Agent Note 格式与文档工具名两道门禁，体量不受约束。

`docs/architecture.md` 因此长到 60,309 字节 / 15,999 个单位 / 357 行 / 27 个小节，是宿主同位置文档的三倍。体量来源是两类与代码同频变化的内容：36 行的逐文件职责表（9,035 字节，最大单节）与整节已知限制（约 18,000 字节）。此外开发节与 README、`AGENTS.md` 三处重复讲同一批开关，末尾还有「P5 已完成」这类实现状态标注。代价是改任何一处实现都要同步改架构文档——而它是「先读再改」的地图，读者还要为这份体量付上下文。

## 决策

### 一个事实一个归属

分层表放 `AGENTS.md`（层 → 管什么 → 不写什么），并断言改代码时只改事实已经变化的那一层，架构文档只在组成、接缝或数据流变化时改。`docs/architecture.md` 只留有序地图：分层、运行时模型、数据流、持久化布局、宿主契约落点。

### 限制与开发各自成文

新建 `docs/limitations.md`（限制是什么、为什么这样取舍）与 `docs/development.md`（开发环境、实例、构建契约、测试机制），原样承接架构文档里对应的两节；README 只留使用者向概览与命令速查，细节链过去。逐文件职责表删除——文件头注释是权威来源，不在文档里再抄一份。阶段编号一并删除，`capability-gaps.md` 开头留一句说明它已不再维护。

### 计数口径：CJK 字符 + 空白分词

`wc -w` 对中文失效（整段算一个词），照搬会把 13,000 汉字的文档测成 2,536 词。改为 CJK 统一表意文字逐字算 1、其余按空白分词，代码块与表格一并计入。口径只求稳定与可解释，不追求与 token 数等价。

### 未登记文档同样变红

只遍历清单内文件会留一条旁路：新增长期文档忘了登记就绕过整套预算。门禁改为「根目录与 `docs/` 的 Markdown 枚举 + 清单比对」，漏登记报 `UNREG` 并退出 1；`tests/doc-budget.test.js` 另守一条真实扫描用例，脚本入口与单测两处能独立变红。

### 天花板按当前值留余量，超限先搬层

清单在 `scripts/doc-budgets.json`，入口 `scripts/verify-doc-budgets.mjs` 接进 `npm run check`。判定红了按「搬到对的层 → 压缩 → 抬天花板」处理，抬天花板要在 PR 里写明理由（与宿主同一规则）。

余量按层定，天花板 ≥ 当前值 × 1.05（每个任务都要改的 `AGENTS.md` 与高频追加的 `capability-gaps.md` ≥ × 1.10），不贴线。理由是计数口径把中文标点也按空白分词计（`AGENTS.md` 单位里约 12% 来自全角标点），5% 只够约 200 个汉字加标点，一次中等规模的规则补充就会撞线；按 3,600 时实际只有 7.8%，与声明的 10% 不符，所以抬到 3,810。抬天花板时按同一比例重算。

`.agents/notes/` 与 `.agents/skills/` 不设预算：前者是历史累积，后者按需加载。

## 边界

- 门禁只判体量，不判归属正确性：把细节搬到错误的文档里，它照样绿。避免重复靠的是分层表，不是机械判定。
- 同一事实写在两处时，只有其中一份先撞天花板才会被发现；两处都短就能长期共存。跨文件的重复比同文件更难发现漂移，所以架构文档与服务层语义、限制清单重复的位置一律留「机制在架构 / 取舍在限制」的指针，不两边各讲一遍。
- 章节搬迁会断锚点链接，本仓没有 Markdown 链接门禁：改结构时 grep 一遍 `architecture.md#`。历史 Agent Note 里的旧锚点保持原样——它们记录的是当时那次同步动作，不是当前权威。
- 预算单位是体量代理，不是 token：中文 1 字与英文 1 词的信息量并不等价，跨语言对比没有意义。
- 注入预算（65,536 字节/链）仍由宿主执行，本仓不重复实现；它只管 `AGENTS.md` 这类指令文件，`docs/` 的体量由本仓门禁管。

## 验证

- `docs/architecture.md`：60,309 字节 / 15,999 单位 → 5,041 单位（-68%）；合并 #66 的卡片写入闸后按分层承接新规则（工具面矩阵与执行时闸进架构、用户可见限制进 `limitations.md`），天花板按 ×1.05 重算为 5,300。
- 其余读数：`AGENTS.md` 3,571 / 3,930（10.1%）、`README.md` 2,942 / 3,090（5.0%）、`README_ZH.md` 4,435 / 4,660（5.1%）、`docs/limitations.md` 5,276 / 5,600（6.1%）、`docs/development.md` 1,686 / 1,780（5.6%）、`docs/capability-gaps.md` 13,739 / 15,150（10.3%）、`docs/usage.md` 4,775 / 5,020（5.1%）、`docs/e2e-testing.md` 4,129 / 4,340（5.1%），全部不低于声明的比例。
- README 拆成英文默认与 `README_ZH.md` 后，两版都只留概览与命令速查，开发节与限制节压缩为 `docs/development.md` / `docs/limitations.md` 的指针；#71 加进来的 e2e 段落也从 README 删掉，只留命令与指针（细节在 `docs/e2e-testing.md`）。
- 逐节比对旧架构文档后补回 4 处丢失项：worker 挂工作区的 fail-open 语义（进限制）、`projects.json` 拖拽改序的笔记入口（回架构表格）、非 `active` 卡不能绑槽位与名册到顶单列挂卡 worker（进限制与架构）、worker 各有一份独立 JSONL（回架构）。
- 架构与服务层语义、限制清单之间的 8 组重复全部收敛成指针（上轮 5 组、本轮 3 组：架构 71 ↔ 限制 43、架构 74 ↔ 限制 39、架构 82 ↔ 限制 24，另收敛限制 14 的机制复述），重复处只剩一处详述。
- 新增 `tests/doc-budget.test.js` 4 条（共 10 条）：大表格与长代码块永久样本、缺失读数为破折号、未登记判定、根与 `docs/` 的 Markdown 全部登记。
- `npm run check`：857 tests / 848 pass / 9 skipped / 0 fail；Agent Note 门禁 56 篇、文档工具名门禁 11 篇、文档预算 11 篇全过。
- 双向验证 A（孤儿文档）：新建 `docs/orphan.md` 不登记 → 门禁报 `UNREG` 并退出 1，单测「根目录与 docs/ 下的 Markdown 全部登记」变红（9 / 1）；撤销门禁入口的未登记比对 → 退出 0，还原后删除该文件 → 10 / 10 绿、退出 0。
- 双向验证 B（计数口径）：把 `countDocUnits` 的 `cjkCount` 恒置 0 → 两条口径用例变红；还原后 10 / 10 绿。
- 双向验证 C（超限入口）：给 `docs/architecture.md` 追加约 3,100 单位 → `OVER 7858 / 5000`、退出 1；还原后 10 篇全绿。
- 双向验证 D（锚点）：全仓 76 个 md、170 条相对链接扫描，修复前 `docs/architecture.md` 末尾指向 `#编辑本文件` → 1 条失效；改成 `#编辑本文件与文档分层` → 0 条。合并 main 的 README 双语后，`docs/limitations.md` 与 `docs/development.md` 指向 README 中文锚点的两处链接改指 `README_ZH.md`，复扫仍为 0 条。
