拆解、派工、盯完成、收产物，由它接手。
注意力回到「要什么」，而不是逐个陪跑。

02 / 主要功能

把串行开发，
改成并行推进。

Leader 拆完就派出去。worker 在各自目录后台开工，
结束自动回报，不用你一个个催。

01 / Worker 常驻根会话 spawn_worker

后台各自开工，进程重启后还能冷恢复；人也可以直接打开它的会话。

02 / Isolation 一人一个 worktree CONVENTION

任务隔离先于并行：各自目录、各自实例，不互相覆盖改动与数据。

03 / Settlement 完成自动结算 AUTO

worker 那一轮结束，机制侧折叠产物并唤醒 Leader。不轮询，也不靠 worker 自觉交作业。

01 / Scope 按项目归属 PROJECT-BOUND

卡片编号全局递增、不复用；跨项目改卡会被拒绝，看板只聚合本项目。

02 / Signal 槽位 + 信号灯 LIVE

谁在执行、跑到哪一步、是不是卡住了，卡面直接读出来。

03 / Drill-down 点一下就到会话 ONE CLICK

点卡看目标、范围、验收与链接；点槽位直接进那个 worker 的会话接着聊。

leader-mode

给 Leader 的分阶段 playbook，不是一句「你是 tech lead」。

讨论 → 设计 → 交付 → 审查 → 合入

三份东西各管一层，都只贡献提示词，不授予工具权限。

05 / 主要功能

不是全自动，
是随时可介入。

Agent 还不够完善，人仍在回路里。
区别是：你只在需要的时候出现。

01 / DRILL DOWN

下钻

点开任意 worker 的会话，绕过 Leader 直接对话、直接推进。

02 / READ ONLY

回看

用 read_worker_session 复盘每一轮：任务、正文、调过哪些工具、哪步失败。不唤醒，不产生模型调用。

03 / STALL WATCH

巡查

15 分钟没有回报，机制侧给 Leader 一条提醒：哪张卡、挂了多久、最后回报在哪。

Leader 能纠偏，但无法中止 worker；真卡死，人去那个会话里处理。

06 / 对比

和 Agent Team
模式，差在哪？

维度
dsh-leader-agent
Harness Agent Team
组织
项目：一个项目一个 Leader + 一块看板
会话：根会话开启 Team，整棵 subagent 树共用一块任务板
成员
常驻根会话 worker，可冷恢复、可下钻
可继续 subagent teammate，通过标准 subagent 工具寻址
工作区
约定一人一个 worktree，任务隔离
成员共享同一检出目录，不提供 worktree
任务
项目绑定卡片 + 槽位 + 实时信号灯
共享任务板 + 依赖 / 认领 / 写域提示
人的位置
项目树、标签栏、下钻、随时纠偏
标准 subagent 导航，send_message / interrupt_agent
结算
turn 结束自动结算 + 唤醒 + 15 分钟巡查
完成通知 + wait_agent；任务更新不唤醒成员

Team 是运行时的协作原语；Leader Agent 是面向交付的编排层。

不建议同时启用：worker 会被 Team 当成隐式 Lead。
